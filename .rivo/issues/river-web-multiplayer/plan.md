状态：执行中。依据：用户于 2026-11-02 确认采用权威状态模型，并授权精简、重构现有实现，直接自查和验证，不再组织多轮代理审阅。

## 目标与规模

River 是个人娱乐项目。一个 Node 进程托管若干好友房，每房最多十个座位。Web 与 Electron 共用界面、协议和牌局逻辑。个人昵称与战绩保存在本地，不建设账号、钱包或商业平台基础设施。

已确认功能仍以 [产品决定](product-decisions.md) 为准：邀请加入、真人与独立 AI 玩家、自由聊天、手中买卖筹码、自选亮一张/两张、计时、预约动作、暂停、房主转让、观战透视与盈亏。API Key 与模型调用留在 Electron Node。

## 权威状态

一场牌局只有一个 RoomState。它包含玩家、座位、本手规则、完整牌堆和底牌、公共牌、底池与边池、行动位、计时、资金流水和手牌记录。运行时持有它，客户端只持有自己有权看到的 RoomView。

```ts
nextState = apply(state, command)
view = project(nextState, playerId)
```

同一房间所有操作进入一条 Promise 队列。处理顺序为：解析输入、检查当前规则、生成候选状态、保存、替换当前状态、发布玩家视图。定时器与 Agent 结果也提交操作。不同房间各自执行。

一次变更只保存房间快照与必要的命令回执。资金、出牌和加入重试使用相同 commandId，回执避免重复执行。只读同步和历史查询直接返回结果，不改变版本、不进入待重放命令表。

投影直接按玩家身份生成。每次发送完整 RoomView，事件只用于声音、动画和提示；重连取得最新视图，不补播动画。服务端不保存发送给客户端的投影，不维护投影交付日志。

## 模块

| 模块 | 职责 |
| --- | --- |
| engine | 德扑规则、牌堆、底池和行动；纯计算，复用现有实现 |
| protocol | 命令输入与玩家视图定义；网络输入通过已有 Zod 校验 |
| runtime | 权威 RoomState、串行处理、计时、投影和战绩生成 |
| storage | 玩家数据与房间快照的存储协议 |
| client | 连接、请求响应、最新视图订阅；重连后重新绑定 |
| app | 共享 React 页面，UI = f(RoomView)，手机/平板/桌面布局 |
| server | ws 连接和 SQLite 组装运行时 |
| desktop | IPC 本地运行时、SQLite、safeStorage 与本地 Agent/教练 |
| web | 浏览器 WebSocket、IndexedDB 与共享 app |

优先复用已有 React、ws、Zod、libSQL 和界面组件。不引入消息队列、事件溯源框架、分布式锁或新的状态机库。

## 存储与恢复

SQLite 保存 rooms 快照和 command receipts；玩家信息已经包含在快照，不建 controller 镜像表。按同一事务保存状态与回执，成功后才发送确认。写失败保留原状态并报告错误；不在后台猜测补偿。

每次有效操作保存计时剩余值。服务重启恢复最后快照，给予连接宽限，再继续保存的行动/展示时间；恢复后可能多出从最后一次保存起经过的时间，娱乐项目接受这个误差，不为精确秒数周期写整房快照。

只有一个服务实例和一个房间写入者，版本用于标识更新和检查程序错误，不自动重载重试版本冲突。数据库整体不可用时停止接单，重启恢复。

全部真人离开后关闭房间；尚未结算的投入单列中止，不伪造赢家。关闭后的记录供已有凭证取回，保留七天后清理。

个人战绩按 roomId/handId 或 fundingId 覆盖保存；重连按普通分页补取记录，重复写同一个记录不重复累计。只传完整 JSON 记录，不实现 Base64 分块和多级 revision 协议。晚亮牌更新同一手的可见牌槽。

## 规则边界

- 牌桌与筹码由运行时决定。客户端不能上传底牌、改池或指定赢家。
- 本手座位归属与可见策略在开手时固定。房间设置修改从下一手生效。
- 玩家资料与手牌座位分开；离桌后保留本手资格信息至结算。非全下离桌管理性弃牌，全下离桌保留争池资格。
- 手中买卖只改未投入筹码；全下后新增买入留待下一手。下注已经投入的筹码不会退回。
- 真人默认 30 秒，超时可过则过、否则弃牌；掉线宽限 60 秒。Agent 使用本地模型调用时限，失败等待房主重试或移除。
- 展示默认 10 秒，房主可跳过。暂停冻结牌局计时，聊天和连接管理继续，最后真人离开仍立即关房。
- Agent 与真人是独立连接；提供 AI 的 Electron 玩家需要房主授权。教练只读本人视图，默认关闭。
- 入房采用本地随机控制凭证，不引入用户中心。凭证只用于保持当前座位归属。

## 界面与接入

Web 入口 /play/，邀请 /play/join/<roomId>；Electron 可输入相同邀请链接。浏览器建房后可以授权 Electron 参与者提供 AI。

共享界面沿用桌面端现有设计体系。牌桌直接使用 @river/ui 的 TableStage、Seat、卡牌、筹码及动画；桌面大厅布局、行布局、操作控件、公屏、Segmented、RichText 和快捷键抽入 @river/ui，由原桌面页面与共享联机页面共同引用。继续使用原 tokens.css、字体、黑白灰卡片及按钮。

共享页面显示牌桌、自己的操作、资金、聊天、房间管理及战绩。手机将聊天和教练放在可切换面板，操作栏固定在可触达位置；十个座位按稳定 seatId 展示。单张亮牌使用固定两槽卡牌。

Electron 继续复用现有模型配置、角色与 safeStorage。共享应用通过宿主能力调用本地 AI 和教练，浏览器没有模型密钥入口。旧历史保留；新战绩不依赖旧 bankroll。
