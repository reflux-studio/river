# 联机界面设计

状态：待确认。依据：桌面端现有设计体系（TopBar、LobbyLayout、TableStage、ActionBar、ChatPanel、CoachPanel、tokens.css）与产品决定 P6/P15/P16/P18/P20/P30/P33/P34。

## 判断

当前联机页的问题不是组件不够，而是没有沿用桌面端的设计语言：

- `packages/app/src/style.css` 另起了一套 `.river-*` 按钮、输入框和面板，和桌面的 Tailwind + tokens + 组件写法并行。
- 房间条把返回、邀请、公屏、管理、开始首手、暂停、断线状态混成一行文字按钮，没有主次。
- 亮牌、计时、观战胜率、房间管理只是把命令绑到按钮上，没有设计过状态和反馈。
- 公屏只有自由聊天，没有牌局行动记录；桌面端公屏里的系统消息和行动消息没有对应物。

## 设计原则

1. 同一套桌面语言：白卡片、14px 圆角、1px `--border`、13/15/28px 字号、黑色胶囊主按钮、白色描边次按钮。
2. 一屏一个主动作；房间管理收进右侧面板，不堆在牌桌顶部。
3. 牌桌是主角：桌面上只留悬浮胶囊（手数/街道、声音、外观），其他信息进侧栏。
4. 禁用要说明原因；破坏性操作二次确认；倒计时来自服务端 `deadlineAt`。
5. 手机不是缩小版桌面：牌桌占满，操作栏固定底部，公屏/教练/管理用底部面板切换。

沿用桌面 TopBar：

```
│ ◉ River   大厅   战绩                          ● 已连接      │ 52px
├──────────────────────────────────────────────────────────────┤
```

- 导航选中项浅灰底加粗，和桌面一致。
- 右侧只留连接状态；断线时变红点并显示“重连中”。
- 移除顶栏的“声音开/关”，声音属于牌桌偏好。

### 3. 房间外壳

```
┌──────────────────────────────────────────────────────────────┐
│ ‹  好友房 585bf5f3 · 5/10          [邀请] [公屏] [房间]      │ 48px
├──────────────────────────────────────────────────────────────┤
```

- 左侧返回大厅；房号点按复制完整链接。
- 邀请、公屏、房间是白色胶囊；小屏统一只显示图标，大屏显示图标 + 文字。
- 开始首手在底部操作区，只在房主未开局时出现；房间条不再放主按钮。
- 暂停、断线、重连接收状态用胶囊显示在房间条右侧，不用 `<strong>`。
- 主机操作（暂停、下一手、散桌、规则）全部收进“房间”面板，房间条不重复。


- 空位改成虚线圆 + 座位号，不再画完整白卡；只有自己未入座时显示“入座”按钮。
- 手数/街道用左上角一个白色胶囊，街道走 i18n（翻牌前/翻牌/转牌/河牌）。
- 声音和外观复用桌面右上角的悬浮胶囊和 `AppearancePopover`。
- 行动座位：蓝色描边 + 座位下方一条倒计时进度条；状态胶囊写“行动中”，不显示秒数。

- 发牌：接入 `dealId`、`dealOrder`、`onDealStart`，逐张动画与声音和桌面一致。

- 第一行是加注预设 + 右侧状态与剩余时间进度条，不显示秒数。

- 房主未开局时，右侧显示“开始首手”主按钮；常驻房间条不再放这个按钮。
- 轮到自己时状态变蓝，加注输入聚焦。
- 预约操作已按用户要求移除，不保留独立入口。

## 组件与样式

- 新增共享组件：`Panel`、`PanelHeader`、`PillButton`、`PrimaryButton`、`FieldRow`、`SwitchRow`、`EmptyState`、`Kpi`、`SidePanel`、`BottomSheet`。
- 只抽桌面和 Web 都在用的；不预建“以后可能用”的变体。
- 删除 `packages/app/src/style.css` 里的按钮/输入/面板重置样式，只保留牌桌容器、移动端面板和少量布局。
- 统一 i18n：新增 `web` 词条，复用 `poker` 术语；不再在组件里写中文。
- 桌面端把 `components/ui/toggle*` 的转发保留，避免两份 Radix 实现。

## 交互规则

1. 一个区域只有一个主按钮；主按钮在右下或操作区最右。
2. 禁用按钮必须有可见原因（例如“等待房主开始”“已亮牌”）。
3. 破坏性操作（散桌、移除、转让房主）二次确认。
4. 所有服务端拒绝显示成人话，不直接 `String(error)`。
5. 桌面快捷键沿用 F/C/R/N；手机不显示快捷键。
6. 断线、重连、暂停用状态胶囊，不遮挡牌桌操作。

## 实施顺序

1. 基础组件 + 外壳 + 大厅。
2. 房间条 + 牌桌覆盖层 + 操作区。
3. 房间面板 + 公屏 + 教练 + 移动端。
4. 战绩页 + i18n。
5. 发牌动画/音效接入，复用桌面音频控制器。

## 实现状态（2026-11-03）

已完成：外壳、大厅、房间条（小屏统一图标）、牌桌覆盖层（空位点击入座）、操作区（预设、计时进度）、亮牌浮层（手机胶囊 + 翻牌动画）、手机座位头像、房间面板（桌面右侧栏 / 手机底部面板）、公屏行动流、私有教练、战绩页、逐张发牌音效、中英文文案。

已移除：预约操作及其协议/运行时状态（用户 2026-11-03 要求，不新增额外能力）。

已知差异：

- 公屏行动流来自本次连接收到的 effects，重连后不补历史行动；后续可在 `RoomView` 增加公开日志字段。
- 亮牌的“已亮”状态保存在本地，重连后不会从视图恢复。
- 房间设置仍受 runtime 限制，只能手间修改；面板在非 waiting 阶段显示“本手进行中，下一手开始前可改”。
- 手机公屏和教练是左右抽屉，房间管理是底部面板，没有合并成同一组 tab。

## 本轮不做

- 不新增 runtime 能力；除按用户要求移除预约操作外，不改权威状态、协议字段和存储。代码审阅发现的过度设计单独处理。
- 不做深色模式、语音、表情、排行榜。
- 不新增产品规则；亮牌、计时、观战按现有产品决定。
