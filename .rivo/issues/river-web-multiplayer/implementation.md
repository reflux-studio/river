# River Web 与好友联机实施记录

依据：plan.md v2、产品决定与现有桌面设计体系。实现已在本地提交，未部署。

## 已实现

- 单个权威 RoomState，按房间串行处理操作；SQLite 同事务保存状态及必要回执，再推送各玩家可见视图。WS 与 Electron 本地连接使用同一运行时。
- 十人好友房、邀请链接、本地身份及个人战绩；买卖筹码、单张/双张亮牌、计时、掉线移除与房主转让、暂停及公屏。预约操作已按用户 2026-11-03 的要求移除。
- Electron 使用原本地模型配置与 safeStorage，提供独立 AI 连接和私有教练。浏览器没有模型密钥入口。
- Web 与 Electron 共用 packages/app 页面。牌桌复用现有 TableStage、Seat、筹码、卡牌和动画；原桌面大厅布局、操作控件、公屏、分段控件、牌面文本和快捷键抽入 packages/ui，原页面与新联机页使用同一实现。继续使用原字体、tokens.css 与黑白灰界面。Electron 外观设置沿用现有 settings。
- 亮牌改为牌桌右下角的小浮层：桌面 216px，手机默认收起为“亮牌”胶囊、展开后 132px；不占用底部操作区，不覆盖自己的底牌。亮出后卡片翻转一圈，其他玩家看到底牌翻入。
- 创建/加入房间增加 20 秒兜底和分阶段超时；短房号在本地校验并给出可读提示，不再抛 Zod 原始错误。客户端与服务端输出 `[river]` 日志，覆盖连接、绑定、拒绝、超时、命令和被丢弃的无效消息。
- `crypto.randomUUID` 只在安全上下文可用；局域网 HTTP 打开时改用 `createId`（`crypto.getRandomValues` 兜底）。此前非安全上下文会在 `RiverApp` 初始化时抛错，页面停在空白/加载态。
- 同一凭证在另一个标签页恢复会话时，旧连接收到 4001 后停止重连并提示，避免两个标签页互相顶号。绑定前积压的命令只重放一次，不会在首个投影时把刚发出的买入重复发送。
