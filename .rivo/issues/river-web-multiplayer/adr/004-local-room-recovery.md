# 004：使用服务端本地持久化恢复房间

状态：接受（用户，2026-11-02）
依赖：001、002
影响模块：F2、F3、F4

## 背景

下注即时成立且掉线不退款。仅内存房间在服务重启后不能可靠恢复未结算底池；用户明确要求增加本地持久化。

## 可行选项

仅内存房间实现较少，但需接受服务故障丢局和人工处理。服务端本地保存权威房间状态可恢复牌局，无需账号或远程数据库，但必须设计一致提交与恢复。

## 决定与理由

采用单机本地房间持久化。推荐本地 SQLite 加原子状态/命令结果记录，具体库在方案核对。它只保存房间权威状态，不承担长期用户资料与个人战绩中心。

## 后果

需保存恢复必要的剩余牌堆、座位、筹码/底池、行动权、决策标识、暂停状态与命令去重信息。数据库提交后才确认已接受命令并发布结果；落库失败不对外宣布成立。恢复需给控制端重新连接机会，过期 Agent 尝试失效。全部真人退出后已关闭的房间不恢复，已关闭记录与存续状态必须区分。单机进程恢复不等于磁盘损坏容灾或多实例高可用，容量与保留时间仍需核对。
