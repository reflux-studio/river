# 002：本地身份与本地 Agent，公共服务仅承载房间牌局

状态：接受（用户，2026-11-02；补记）
依赖：001
影响模块：F2、F4、F5

## 背景

用途以朋友娱乐局为主。讨论曾提出账号、云端模型配置及服务端执行 Agent，用户明确希望避免复杂中心服务，使用本地玩家资料，并将 API Key 留在 Electron 本机加密存储。

## 可行选项

公共服务保存账号、记录和模型凭证并执行 AI，可统一托管，但引入用户体系、密钥托管和费用边界。另一种是身份与长期记录留在本机，公共服务管理临时牌局，Electron 本地 Agent 作为座位控制端发送动作。

## 决定与理由

采用后者。无注册登录与中心战绩；Web 不创建本地 Agent。Electron 房主或获授权参与者保有 Key 和模型调用，服务端只接收动作和公开台词。用户认可本地 AI 宿主可接触其托管 AI 底牌的娱乐局取舍。

## 后果

用户本地 ID 不等于可信资产账户。仍需房间内连接与座位控制绑定。真人、Agent 与管理权分别维护状态，房主离线不推导 Agent 离线。长期资料不跨设备同步，不维护长期筹码钱包。临时房间已由 ADR-004 决定本地持久化，这不增加用户中心。
