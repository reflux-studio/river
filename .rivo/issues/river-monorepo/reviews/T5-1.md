## 判断

### 需求与契约：符合

- **engine**：`handName` 改名为 `handCat`，返回 `HandCat`，这个类型的 12 个取值与契约一致；`PotWin.handCat: HandCat | null`。`pokerZh.hand` 加了 `satisfies Record<HandCat, string>`。
- **sysKind**：runner 中所有系统消息都经过 `sys(sysKind, …)` 写入。一共 5 处：`seat`（入座）、`rebuy`（重新买入）、`hand`（第 N 手）、`street`（发牌）、`win`（赢得）。仓库中已经没有别的 `kind: 'sys'` 写入点。`newChat` 改为按 `sysKind === 'hand' || sysKind === 'rebuy'` 判断，原来的中文正则已删除。`needsSettings` 只删了“解密”分支，其余部分没动。
- **手牌记录**：`label`、`pos`、`handName` 按当前语言写入文字，字段结构不变。实测中文下落库的记录与改动前逐字一致（见“实际验证”第 3 条）。
- **提示词**：对手和教练的 system 都在末尾加了 `reply`，中文为“请用中文回复。”，英文为“Reply in English.”。`COACH_ASKS` 移到 `prompt.asks`，教练风格从 `prompt.coaches` 取，符合“工程注意事项”。
- **工具定义**：act、talk、recap、ping 都改成函数，description 和 `.describe()` 按 locale 取值。
- **启动失败弹窗**：使用 `dict(resolveLocale(app.getLocale()))`。
- **依赖方向**：main 只新增了对 `@river/i18n` 的引用，符合 ADR-007。
- **渲染进程**：只改了 `CoachPanel.tsx` 一行，改为 `dict('zh').poker.hand[nums.handCat]`，这是契约允许的临时中文映射。`Replays.tsx`、`Settings.tsx` 里剩下的 `dict('zh')` 属于 T6 的范围。没有超范围改动。
- **ADR-006**：`Thread` 的结构没有变化，包括按组保留本手、往手压缩成摘要、5 手窗口、tool-call 与 tool-result 的写法、`chatSeen` 和 `lastSituation`。改动只是把两处文字换成字典取值。中文下实测完全一致（见“实际验证”第 3 条）。

### 自报偏差的判断

1. **中文 system 末尾加“请用中文回复。”**：这是 `task.md` 契约“中英两份都在开头或结尾写明”的直接要求，不算偏差。
2. **截断长度按语言区分（中文 40/30 字符，英文 120/120 字符）**：判断为固定内容范围内合理的实现细节，不需要用户决定。理由如下：
   - 中文长度与改动前逐字一致，老用户的行为没有变。
   - 截断长度的作用是配合提示词里的长度约束。英文提示词把“20 字/30 字”换算成“15/20 words”，如果沿用 40 个字符，英文会被截在单词中间，等于英文功能不可用，所以这是翻译的必然配套。
   - 英文没有旧行为，谈不上改变行为。
   - 有一点值得知道：英文的印象（note）上限从 30 提高到 120 个字符，写进 `river_memory` 的短印象，以及随后拼进 system 的内容会比中文长。这在预期范围内，记为 F3。
3. **英文字数改为词数**：属于忠实翻译的范围，见下文抽查。
4. **英文工具结果的键名为 actual/chat**：中文键名仍是“实际/公屏”，不变；英文如果保留中文键名，就违反“无汉字”要求。合理。
5. **saveProvider 错误和 ping 也做了本地化**：属于 plan 表中“IPC 返回给界面的错误信息”，合理。
6. **英文玩家头像字母用 Y**：属于展示文字，合理。
7. **COACH_ASKS 移到 prompt.asks**：这是 task 的要求。

### 英文翻译忠实度（抽查）

- **对手 system**：人设、“别做明显送钱的离谱决定”、只能看到自己的底牌和公开信息、act 各字段的含义、raise 即下注、to 为总额、“不要如实报出底牌”、不想说就留空、talk 可以口嗨和撒谎，全部保留。“中文口语”对应为“casual spoken English”，恰当。
- **教练 system**：站在玩家一边、不假装知道对手底牌、按新手或有基础调整措辞、牌面写成“A♠”、不用 markdown 标题或列表、三种时刻、按决策质量评价而不以结果论，全部保留。“回答用中文，可夹少量英文术语”这一句被删掉，由末尾的“Reply in English.”取代，合理。
- **字数约束**：
  - 150 字 → 100 words
  - 80 字 → 50 words
  - 28 字 → 20 words
  - 50 字 → 35 words
  - 30 字 → 20 words
  - 20 字 → 15 words

  换算尺度一致，每一条约束都保留了。
- **局面描述**：
  - 底池赔率、需跟注、可选行动（包括“下注/加注到总额 min~max”）、座位顺序（小盲起、按钮收尾）、“本手共投入（含本轮）”，都保留了。
  - 可选行动去掉了中文括注，例如 `check（过牌）` 译为 `check`，合理。
  - 小瑕疵：“当前牌型”译为 `current hand`，与同一段里 `hand N` 的“手”撞词，见 F4。
- **工具说明**：act、talk、recap 的每个字段都能逐条对上，“没有留空”这类约束也保留了。

### 工程质量：良好

- 每次调用时按 `settingsCache.locale` 取字典，没有缓存。这与“运行期间语言不变”的前提一致，代码也简单。
- 词条带参数时写成函数，`en: typeof zh` 在编译期保证没有漏翻的词条。
- 一点可商榷之处：`prompt.limits` 是数值配置，放进了文案字典。它与提示词中的长度约束成对出现，放在一起便于同步修改，可以接受，记为 F3。

### 验收证据：总体充分，有一处小缺口

- 我独立复跑了 typecheck、test 和 build，都通过。
- 英文压测走的是真实的 Agent 和 `callModel`，收集的内容包括：system、全部 messages（含 thread 中的 tool-call 和 tool-result、往手回顾）、工具定义（name、description、inputSchema），以及 TableView、公屏、教练条目和落库的记录。
- 我用注入标记的方法做了反向验证，覆盖面可信（见“实际验证”第 4 条）。
- 唯一没有覆盖的发给模型的词条是 `desktop.model.heroView`，见 F1。

## 实际验证

1. **根目录 `pnpm typecheck`**：engine、i18n、ui、desktop 都显示 Done。
2. **根目录 `pnpm test`**：engine 36、i18n 4、ui 5、desktop 110，全部通过。`git diff --stat` 确认 desktop 的测试只新增了 `english.test.ts` 并改了 `mock-model.ts`，原有 107 个用例一行没改。
3. **中文模式与改动前逐字对比**（重点项）：
   - 做法：用 `git archive 56ecf8e` 把旧代码取到 scratchpad，node_modules 用符号链接接到现有依赖，工作区的包解析到旧版本。两棵代码树运行同一个临时用例：中文（不调用 `completeOnboarding`）、同一个种子的随机 mock 模型，自由局 4 人和教练局 3 人各打 20 手，含提问。导出全部模型调用的 system、prompt（含 thread）、工具定义，以及公屏、TableView 和落库记录，去掉 id、时间戳等不确定字段后做 diff。
   - 结果：两边都是 461 次模型调用。差异只有 3 类：
     - 每个 system 末尾多一行“请用中文回复。”；
     - 公屏消息多了 `sysKind` 字段（195 处）；
     - TableView 的 `nums.handName: "高牌"` 变为 `handCat: "highCard"`（1202 处，渲染进程仍显示中文）。
   - 结论：prompt（含往手摘要、工具调用记录、观察保留）、工具的 description 和 schema、落库记录全部逐字相同，没有任何语义或措辞差异。
   - 另外，我把旧代码中全部 143 个中文字面量逐段对照新字典做了检查，没有对上的 7 段都只是拼接位置不同，拼出来的结果相同。
   - 临时文件用后已删除。
4. **english.test 的反向验证**：
   - 做法：在一个临时用例里给 `dict('en')` 的 31 个词条注入带汉字的编号标记，覆盖工具的 description 和 `.describe()`、对手和教练 system 的各段、`asks` 的全部 4 条、`pastHands`、`pastHand`、`digest`、`recapDigest`、`coachDigest`、`talkAsk`、`talkSaid`、`toolResult` 键名、局面头部、公屏 hand、rebuy、afterHand 等。然后按 english.test 的方式跑两局，查看哪些标记被收集到。
   - 结果：30/31 命中，只有 `heroView` 没有命中（F1）。由此可以确认，工具定义、COACH_ASKS、recap、赛后发言、thread 摘要都进入了断言范围，反向验证可信。
   - 临时文件已删除。
5. **静态检查**：`rg -n '\p{Han}' apps/desktop/src/main -g '*.ts'` 排除整行注释后，只剩 `db/index.ts:102` 的行尾注释。ipc、提供方类型名、updater、启动失败弹窗、ping 都已改为字典取值。
