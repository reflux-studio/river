## 判断

### 需求与契约

- **build.yml**（逐步对照旧版）：
  | 步骤 | 新目录下是否正确 | 依据 |
  | --- | --- | --- |

  | prices | 正确 | `apps/desktop/scripts/prices.mjs` 存在，输出用 `new URL('../src/main/models/prices.json', import.meta.url)`，与 cwd 无关；有 `shell: bash` 以支持 `\|\| echo` |
  | 版本号 | 正确 | cwd=apps/desktop 时 `require('./package.json').version` 本地得 `0.2.1`；写入 `$GITHUB_ENV` 为全局，后续步骤可见 |
  | 导入证书 | 不需要工作目录 | 只在 cwd 写临时 `cert.p12/cert.pem` 并用全局 keychain；与 cwd 无关 |
  | 打包 | 正确 | `pnpm build` = `electron-vite build`；`apps/desktop/node_modules/.bin/electron-builder` 存在；`electron-builder.yml` 在 apps/desktop，默认按 cwd 查找；`-c.*` 参数未变 |
  | codesign 断言 | 正确 | 本地 `apps/desktop/dist/mac-arm64/` 与 `River-0.2.1-arm64.{dmg,zip}` 均存在，路径与产物名一致 |

- **pnpm 版本**：`pnpm/action-setup@v4` 未设 `version`，默认读仓库根 `package.json` 的 `packageManager`（`pnpm@11.22.0`）。`apps/desktop/package.json` 也有同值 `packageManager`，action 不读它，pnpm 对非根包的该字段也不生效，当前无冲突（见 F4）。main @ 1ece50c 起就是 `pnpm@11.22.0` + `action-setup@v4`，v0.2.1 已按此发布，组合有先例。
- **setup-node `cache: pnpm`**：lockfile 在仓库根（`pnpm-lock.yaml`），默认 `**/pnpm-lock.yaml` 能命中；action-setup 在 setup-node 之前，顺序正确。
- **ci.yml**：`pull_request` + `push: main`、ubuntu、`pnpm install --frozen-lockfile && typecheck && test`，与任务一致。`pnpm -r` 覆盖 engine/ui/i18n/site/desktop 五个包（本地 typecheck 显示 site 的 `astro check` 与各 packages 均参与）。不含 `build:site`，见 F3。
- **site.yml**：与官方 astro 示例一致——`upload-pages-artifact@v3` + `deploy-pages@v5`（示例原文如此）、权限 `contents: read / pages: write / id-token: write`、`concurrency: pages` 且不取消进行中的、deploy job `environment: github-pages` 与 `url`。上传 `apps/site/dist` 与 `astro.config.mjs`（未设 `outDir`）默认输出一致。`site: https://reflux-studio.github.io` + `base: '/river'` 与 `origin` 为 `reflux-studio/river` 的项目页一致。未用 `configure-pages`：base 写死在配置里，不需要注入，合理。paths 与任务所列三项一致，但有遗漏，见 F2。
- **官网引用仓库其他目录**：`apps/site/src/styles/site.css` 的 `@source '../../../../packages/ui/src'` 落在 `packages/**` 内；未发现对 `.rivo`、`design/`、`apps/desktop` 的构建期引用（store.ts 中只是注释）。
- **knowledge README**（抽查 14 条，均与代码一致）：
  1. `tsconfig.node.json` 不开 jsx（只有 `tsconfig.web.json` 有 `"jsx"`）；
  2. `ipc.ts:55` 对含 `locale` 的 `settings.update` 抛错；
  3. `db/index.ts:153` 已引导而无 locale 的老用户固定 `zh`，否则按系统语言；
  4. `resolveLocale` 为 `/^zh/i` → zh，否则 en；引导页用 `settings.locale` 作预选；
  5. `completeOnboarding` 中 `en` + `cny` → `usd`；
  6. `dict.ts:432` `en: typeof zh`；
  7. `apps/site/src/i18n/site.ts`、`apps/site/src/sim/` 存在；
  8. `updater.ts` `CHECK_MS = 6h`、`autoDownload = true`，`index.ts:66` 仅 `app.isPackaged` 时 `initUpdater`，`ipc.ts:133` `update.check`；
  9. `store.ts` 请求 `releases/latest`，`ASSET` 按 `-arm64.dmg`/`-setup.exe`/`.AppImage` 匹配，与 `electron-builder.yml` 的 artifactName 互相注释；
  10. 三个包在 desktop `devDependencies` 为 `workspace:*`；
  11. 结构图列出的 `table/*`、`agents/*`、`models/resolve.ts`、`db/index.ts`、`updater.ts` 均在 `apps/desktop/src/main/`，engine 的 `table.ts`/`eval.ts` 在 `packages/engine/src/`；
  12. `situation`、`opponentSummary`、`publicHandResult`、`heroHandSummary`、`holeAfter`、`coachBusy`、`chatSeen`、`MEMORY_KEEP` 仍在所述文件中；
  13. 打包（dmg+zip、自签证书、hardened runtime 关闭）与 `electron-builder.yml`、build.yml 一致；
  14. CI 三个 workflow 的描述与文件一致；ADR-005/007 链接目标存在。
- **根 README**：`dev:site`、`build:site` 在根 `package.json` 存在；`pnpm dist` 输出到 `apps/desktop/dist/` 正确；官网地址与 base 一致（合并并首次部署后才可访问，执行报告已自述）。
- 与 ADR-005 一致：仍在 macOS 用固定自签身份签名并断言，发布为正式 Release，上传 `latest*.yml` 与 blockmap。
