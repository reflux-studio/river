主体实现与 task 一致：各模式参数、意图取舍、Memory 配置与 thread/resource 命名、readOnly 复盘、`resolveModel`/`modelReady`/`testProvider`，以及 API key 不外泄都成立；信息隔离测试用的是真实引擎，并且能区分泄露。下面两项需要在交付前修改：

### 3. 意图、泄牌、队列

| 项 | 判断 |
| --- | --- |
| 意图取舍 | `recordIntent` 只写入第一个；`coachAlert` 有 pause 时取 pause，否则取 hint。符合 task |

### D1：`HandLogEntry.board` 的类型

- 原型第 628 行记录 `board: !!x.board`，第 846 行的回放页用 `x.board ? x.label : ''` 判断，引擎 `LogEntry.board` 也是 boolean。T3 的 task 只写了字段名，没有写类型，`types.ts` 选了 `Card[]`。
- 问题：空数组 `[]` 在 JS 里为真。T8 如果照搬原型的回放逻辑，每一行行动都会被当成发牌行。
- 归属：这是 T3 共享类型与原型不一致（task 描述没有写类型）。目前的使用方只有 T3/T4 的测试夹具，T5 还没有开始，现在修改成本最低。
- 建议：在本轮修复中把 `HandLogEntry.board` 改为 `boolean`，同步修改 `db.test.ts`、`views.test.ts` 的夹具，`heroHandSummary` 改用 `x.board` 判断（同时处理 F5）。按共同约定，在 task.md 的 T3 或 T4 结果中记录这次共享类型修改。
