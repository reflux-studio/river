新的 `noHoleLeak`（`test/runner.test.ts` 第 17–27 行）只依赖 `h.runner.game`，不再 import `revealed`（`view.ts` 也已不再导出它）。规则如下：

```
对每个非玩家座位：
  允许出现  ⇔  g.done && g.showdown && !folded
```

## N1 核对

`app.bootstrap` 中，`setImmediate(() => runner.replay())` 现在排在最后一个 `await getOnboarded()` 之后，后面到 `return` 都是同步代码。

```
handler: await getPromptOverrides → await getOnboarded → setImmediate(replay) 入队 → return（同步）
            │
            └─ promise resolve → ipcMain.handle 的 await 继续执行（微任务）→ 发送回复
                                                    │
                          微任务全部清空之后 ─────────┘ → check 阶段：replay() → table:view / coach:alert / breaker
```

在 Node 的事件循环中，微任务总是先于 `setImmediate` 执行，所以不管数据库读取要多久，主进程都会先发出命令的回复，再发出补发事件。**探针 P1'**：用假的 `ipc.handle` 模拟 Electron 的“await handler 后同步回复”，结果是 `reply` 早于第一个 `table:view`/`breaker`，通过。

跨进程的到达顺序由 Electron 的 IPC 通道决定，不在本任务的控制范围内。这一点已经由 `RiverApi` 上的约定兜住：先注册监听再调用 bootstrap，公屏按消息 id 去重。所以 Renderer 不依赖到达顺序也是正确的。
