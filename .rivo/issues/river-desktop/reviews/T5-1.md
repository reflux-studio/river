## 重点检查

### 1. 信息隔离

- `view.ts`：只有满足 `revealed`（玩家本人，或 `street==='showdown' && g.showdown && !folded`）的座位才带 `cards`；与原型第 697 行一致。座位状态里的 `handName` 只在摊牌街出现；引擎只在 `showdown()` 中给未弃牌者写 `handName`，所有人弃牌时赢家的 `handName` 为 `''`（`poker.ts` 第 227 行），所以状态与结果文字都不会泄露牌型。`nums` 只算座位 0。
- 公屏上所有对手发言都经过 `filterSay`：`commitOpponent`（decide 与托管预设台词）一处，`postSay`（chat、win、预设 win）一处。气泡用的是过滤后的文本。
- HandRecord 的 `hole` 只给玩家和摊牌者，与原型 `rec` 一致。它通过 `hands.get` 传给 Renderer，也通过 `publicHandResult` 写进对手 thread，但没有测试覆盖（F2）。
- API key：`provider.save` 与 bootstrap 都只返回 `ProviderPublic`（`keyTail`）；IPC 用例断言 bootstrap JSON 中不含 `sk-`。
- preload 只暴露 `invoke` 和 `on` 两个函数；`contextIsolation: true`、`nodeIntegration: false`；没有关闭 `sandbox`，Electron 44 默认启用沙箱，preload 是 `.cjs`，只引用了 `electron`，与沙箱兼容。`invoke` 和 `on` 在运行时不校验通道名，但主进程只注册 Commands、只发送 Events，因此暴露面没有超出契约。

### 2. 主循环

| 项 | 实现 | 判断 |
| --- | --- | --- |
| 过期丢弃 | decide 返回后检查 `runId`、手号和 `log.length`；proactive 检查 `rid`，并要求 `heroKey` 与当前决策点都等于 key；chat 与 win 检查 `rid`，win 还检查手号 | 符合 |
| 暂停挂起与 resume | `pendingAI` 带手号、logLen、座位；resume 时在 `!done` 且这三项都一致时才提交，否则调用 `loop()` | 符合（比原型更严） |
| 托管与熔断 | decide 失败（超时、抛错、`ok` 为 false、没有 act、被丢弃）就托管；离桌时不计数（`leave.aborted`，且 `rid` 检查在前）。教练用 `isFailure` 判断：被抢占、被丢弃、aborted 都不计 | 符合 |
| deadline 与 `queue.run` 赛跑 | `guarded` 在 `run` 之前启动计时器，并用 `Promise.race` 等待 | 符合 T4 衔接约定。**探针 P3**：给所有对手队列各塞一个永不结束的 durable 任务，决策没有开始（`calls=0`），10 秒后照常托管，失败计数 +1，牌局没有卡住 |
| 离桌 | `runId++`、abort `leaveController`、`game=null`、清空状态、推送 `table:view null`，余额写库；入座时新建 controller | 符合 |
| heroKey 去重 | 入座与 `nextHand` 时清空；resume 回到同一决策点时直接返回 | 符合 |
| runout | 900 ms 步进，由 `rid` 守卫；`TableView.runout` 用于显示“发牌中…” | 符合。**探针 P4**：全下 runout 期间提问会置 `paused`，但 runout 继续（与伪代码一致），一手结束时清除暂停，ask 结束后才自动发下一手 |
| 对手自动重新买入、rebuy、`table.start` 退回原桌筹码、教学牌局配置 | 与原型第 396–420 行、task 的规定一致 | 符合 |

### 3. 公屏

- triggers：`commitOpponent` 在 `!!text && source==='llm' && kind==='free'` 时触发；chat 回应固定为 false；win 为 true；预设台词为 false；玩家发言为 true。与 plan 的触发表一致。
- `pickResponders` 排除以下对手：发言者本人、`out`、正在决策者、10 秒冷却内者，然后按 `talk` 抽样；弃牌者仍可能被抽中（task 只要求排除 `!out`）。LLM 不可用或熔断时不触发。
- 赢家发言：在一手结束时置 `winSpeechInFlight = hand`；`finally` 中只清除本手号，并调用 `maybeAutoNext`；过期（`rid` 或手号变化）时整体丢弃；成功但没有 say 时不补台词；失败、超时、被丢弃时用预设 win 台词（`triggers:false`）；LLM 不可用或熔断时直接用预设台词。赢家发言排在本手 durable 结果之后，所以会先写入结果，与 plan 一致。

### 4. 教练

- proactive：条件是 `coachOn && modelReady && !trippedCoach && !askInFlight`，抢占运行，12 秒；只有 `heroKey` 未变且仍是玩家决策点时才应用；pause 时 `paused=true`。
- ask：未配置、已熔断、无桌时，都用 `setImmediate` 推送 `coach:done`，保证事件晚于命令返回（用例已断言“调用返回时还没有事件”）；否则设置 `askId`，牌局未结束时暂停，并置 `askInFlight`。只在 `open` 时流式推送 delta；被下一次提问抢占或被丢弃时返回 `interrupted`，并在 `coachThread` 中标记；超时或出错时返回 `failed` 并计数；只有 `askId === requestId` 时才清除 `askInFlight` 并检查自动下一手。
- review：用 `reviewing` 去重，排队运行，45 秒，不受离桌影响；成功时落库并推送；失败、被丢弃、未找到、未配置时都推送带 error 的 `review:done`；不计入熔断。
- `coach:alert` 在 `nextHand` 时清空，教学牌局第 1 手保留开场提醒。

### 5. 持久化与启动

- `index.ts`：按 `initDb → initMastra → runner.init` 顺序串行执行；任一步失败都会弹出错误框并 `app.exit(1)`；IPC 在初始化成功后才注册，窗口也在那之后创建。模块顶层没有调用 `getPath`，T3-1 留下的复查项成立。
- `ELECTRON_RENDERER_URL` 和 `RIVER_LIMIT_DECIDE_MS` 都只在 `!app.isPackaged` 时读取。
- HandRecord 包含 `personaId`、`net`、`log[].autopilot`，`board: !!x.board`；`insertHand` 成功后推送 `hands:changed`；每个对手的结果以 durable 任务写入。
- `before-quit`：有桌时先 `preventDefault` 并执行离桌，离桌过程中再次触发退出也会被拦下；`leave()` 写库完成后才调用 `app.quit()`。`quit-out.json` 在真实主进程中复现了这一流程（99840 + 10050 − 10000 = 99890）。

## 偏差逐条判断

| # | 偏差 | 判断 |
| --- | --- | --- |
| 1 | 熔断后本地决策标为托管并计数 | 可接受。plan 写的是“本桌剩余时间全部托管”，T7 横幅和托管标记依赖这一点；只有 engine 为 llm 且模型已配置时才算托管，用户主动选本地引擎时不算。与用例“`autopilotCount` 在熔断时为 3、之后的行动全部带 autopilot”一致 |
| 2 | 教练提醒要求 heroKey 未变且仍是玩家决策点 | 可接受，比 task 更严，防止一手结束后才迟到的提醒生效 |
| 3 | 同一决策点只允许一次对手决策在途 | 可接受，而且是必要的：没有这条限制时，resume 会重复发起决策，并抢占自己的上一次调用，导致误托管、误计数。变异 M2 证实用例能区分两种行为 |
| 4 | TableView 增加 `runout`；离桌推送 `null`；bootstrap 后补发视图、提醒和熔断状态；`hands.get` 未找到时返回 `null` | 可接受。这些都是共享契约的变化，要写进 T5 结果，供 T6、T7 使用；补发时机见 N1 |
| 5 | 沿用原型或新定的小规则 | 可接受：无需跟注时 fold/call 转为 check（原型第 581 行）；加注不带金额时用默认值；无桌时 ask 返回 failed；复盘返回 `not_configured`/`not_found`；本地引擎也写入每手结果（只是本地写入，能让切回 LLM 后的对手知道之前的牌局） |
| 6 | `table.start` 之后事件只追加，Renderer 入座前自己清空公屏和教练对话 | 可接受：`start()` 内的 `chat:append` 早于命令返回，所以 Renderer 必须在调用 `table.start` **之前**清空。要写进 T5 结果，作为 T7 的约定 |
| — | `shared/types.ts` 中另写了一份与引擎相同的 `Legal` | 可接受，作为权宜之计：Renderer 不能引用主进程模块，迁移引擎被权限拦下。typecheck 只保证单向兼容：`view.ts` 把引擎的 Legal 赋给共享类型，引擎增加字段时不会报错。建议在 T5 结果中记为技术债，等用户允许后改成引擎 `import type { Legal } from shared` |
