## 用户本轮的三条调整（2026-09-24 原话要点）

1. 对手只在轮到自己时做一次 tool call，同时完成下注与发言；不在自己回合就不说话；取消自由发言；玩家也不再发言（公屏只读）；关键词泄牌过滤没必要，靠提示词。
2. 不要本地托管引擎：出错自动重试，仍失败就停下，给手动恢复。调研是否有现成德扑规则引擎。
3. 教练模式下一手结束后亮出已弃牌的手牌帮助学习；教练模式是否应做成“对局类型”，不在对局中开关，是否会更简单。

用户追问（同日）：找到的库只有 6 个 star，是不是德扑基本没有现成的热门引擎。

## 德扑规则引擎调研

当前认识：JS/TS 生态没有像样的“热门”桌面规则引擎。常用的都是牌型评估库（只比大小，不管下注流程）；带完整下注流程的库都很小众。规则上最严谨、有论文和大量测试的是 Python 的 PokerKit，但它无法在 Electron 主进程里直接用。

| 库 | 类型 | 版本 / 发布 | 实测 |
| --- | --- | --- | --- |
| `@pokertools/engine` | TS 桌引擎（Redux 式不可变状态、边池、未跟注退还、单挑、可注入随机数、手牌历史导出） | latest 1.0.20，2026-09-19；2025-11-29 首发，单作者，npm 上共 15 个版本；用户看到 GitHub 约 6 star | 1.0.20：不完整加注正确拒绝再加注；单挑顺序正确；3000 桌 25,730 手随机合法行动，零异常、筹码守恒。1.0.9（2026-06-26 发布；首次安装时本机 npm 解析到的版本）同样压测在库内部抛“筹码守恒被破坏”数百次 |
| `poker-ts` | TS 桌引擎（`Table` 状态机） | 1.5.0，2025-09；2021 首发 | 短码不完整全下后，已行动玩家仍可再加注（规则错误） |
| `@chevtek/poker-engine` | JS 桌引擎，依赖 pokersolver | 1.2.14，2021-07 后未更新 | 未测（停更） |
| `pokersolver`、`phe`、`poker-evaluator` | 只做牌型评估 | 2018–2025 | 不涉及下注流程 |
| PokerKit（Python） | 规则最完整的学术库 | 0.7.6 | 不适用：需要 Python 运行时 |

River 自研引擎（移植自原型 `poker.js`，`src/main/engine/poker.ts` 278 行）实测也有同一处规则错误：短码不完整全下后，已行动玩家仍可再加注（`apply` 对所有其他人重置 `acted`）。另一处偏差：平分底池的余数全部给座位顺序上第一个赢家，规则应从按钮左侧起逐枚分配（审阅 F10 复现：三人平分 41、按钮在座位 1，实得 15/13/13，应为 14/13/14）。

依据：`evidence/research/engine-results.txt` 及同目录脚本（s1/s2/s3/s4/fuzz2）；npm registry 元数据（2026-09-24 读取）。GitHub 与 npm 下载量接口在本会话被代理拦截，热度只能引用用户看到的 star 数。

## Mastra 用量与价格

- `generate` / `stream` 的结果带 `totalUsage`（输入、输出 token），可以记真实用量，不必按字数估算（`@mastra/core/dist/stream/base/output.d.ts` 第 19、217 行）。
- Mastra 随包的 `provider-registry.json` 只有提供方、模型名和端点，没有价格；`TokenCostControl` 处理器的花费估算依赖外部数据，离线不可用。
- 因此“花费”只能来自用户填写的单价；未填时只能显示 token。

## 适用边界

- 引擎结论基于上述场景脚本与随机压测，不等于逐条规则审计；随机压测只校验不崩溃、筹码守恒与能结束，不校验每一步动作合法性判定的正确性。
- Mastra 结论基于 1.69.0 的类型与打包文件，未在本轮实跑单步工具调用的延迟。
