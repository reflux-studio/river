# River v2：方案讨论快照（第 1 轮）

本文件记录讨论收敛出的做法，供独立审阅与用户确认。未经批准前不是最终 plan。调查依据见 `note.md`。

## 1. 原始请求

导入设计项目中的 `River v2.dc.html`（附 `poker.js`、`support.js`）并实现，走 Rivo 流程。用户同时提出（2026-09-24）：

| # | 用户原话要点 |
| --- | --- |
| U1 | 对手每回合只做一次 tool call，同时完成下注和发言；不在自己回合就不说话；取消自由发言；玩家也不发言（公屏只读）；不需要关键词泄牌过滤，诈唬说“我有三个 A”也不违规 |
| U2 | 不做本地托管引擎；出错自动重试，失败就停下，给手动恢复；调研现成德扑规则引擎 |
| U3 | 教练模式下，一手结束亮出已弃牌的手牌；教练模式做成“对局类型”，不在对局中开关 |
| U4 | 追问：找到的库只有 6 star，是不是没有热门引擎 |
| U5 | 引入自动更新；问依赖服务器还是只要 GitHub（记得 Tauri 只要 GitHub） |

设计稿里仍有的公屏输入框、话痨档位、本地引擎兜底、泄牌过滤，以 U1/U2 为准删除。

## 2. 范围

实现 v2 设计稿的全部交互与视觉改动（`note.md` “v1 → v2 设计稿差异”表），并按 U1–U3、U5 改逻辑。

相对 v2 设计稿的有意变化：

| 设计稿 | 本方案 | 原因 |
| --- | --- | --- |
| 公屏输入框、公屏“安静/适中/热闹”档位 | 删除，公屏只读 | U1 |
| 设置“决策引擎：LLM/本地” | 删除 | U2 |
| 对手页“四项倾向”条与滑杆 | 删除（待确认，见 D6） | 只服务本地引擎，U2 后无人使用 |
| 教练栏“主动提醒”开关、“每手复盘”开关 | 删除；由对局类型决定 | U3 |
| 统计按字数估算 token、按 Haiku/Sonnet 固定价 | 用 Mastra 返回的真实 token；价格由用户按模型填写，未填只显示 token | 提供方由用户配置，Mastra 不带价格表 |
| 统计用途含“公屏对话”，KPI 含“本地引擎兜底次数” | 删除这两项 | U1、U2 |
| 本地规则复盘（LLM 超额时） | 删除；复盘失败显示“重试” | U2 |

## 3. 决定点（需用户确认；★ 为推荐）

### D1 对手的单次调用怎么组织（U1）

★ 每次轮到对手：TableRunner 把该座位视角的局面直接写进输入（阶段、底牌、公共牌、底池、需跟注、可选行动与加注范围、各座位公开状态、本手行动、最近 8 条公屏），只开放一个工具 `act({ action, to?, say? })`，`toolChoice: 'required'`（提供方不支持时 `auto`），`maxSteps: 1`。`say` 可空，≤30 字的要求写在提示词里；代码只截断到 60 字以防撑坏气泡。

随之删除：`view_table`、`estimate_equity`、`read_chat`、`hand_history`、`say` 工具；公屏回应（`chatReply`、`pickResponders`、10 秒冷却）；赢家发言（赢家不在自己回合，按 U1 不说话）；玩家 `chat.send`；`filterSay`；消息的 `triggers`、`replyTo`、`autopilot` 字段；角色的“健谈度”字段（话多话少写在提示词里）；预设台词 `LINES` 与角色 `lines`。

胜率参考：原型会把“你对随机手牌的胜率约 x%”写进对手视角。★ 保留这一行（本地蒙特卡洛 150 次，不耗 token），让小模型不至于乱打；也可删掉，完全交给模型判断。

### D2 对手的记忆（U1 的连带问题）

现状：每位对手有 Mastra thread（最近 40 条消息）和 working memory（“牌桌印象”模板），更新 working memory 要额外一次 `updateWorkingMemory` 工具调用。单次调用后这两者都要重新安排，而且最近 40 条消息正是 token 大的主因之一。

| 选项 | 做法 | 代价 |
| --- | --- | --- |
| ★ A 代码维护印象 | `act` 增加可选参数 `note`（≤30 字，对某人的新观察或自己心情）；TableRunner 把它追加到该角色的印象列表（每角色保留最近 12 条，存 SQLite），每次调用写进系统提示。不带会话历史，最近几手的公开结果由代码摘要成 3 行放进输入 | 对手不再用 Mastra Memory；“拟人”靠印象列表与手牌摘要 |
| B 保留 Mastra thread | `lastMessages` 降到 10，印象仍用 A 的 `note` 方式 | token 仍随桌上时长增长 |
| C 不要记忆 | 每次调用只看当前局面 | 最省；对手不会“记仇” |

注意：A 改变了上一轮“对手记忆用 Mastra working memory”的实现（上一轮用户决定是“尽量拟人，委托 AI 定”），需用户知情。

### D3 失败处理（U2）

★ 对手调用：单次 20 秒超时；失败自动重试 2 次（间隔 1 秒、3 秒）；仍失败则本桌暂停（新状态 `stalled`），操作区上方显示“阿狸 的模型调用失败：<原因>”与「重试」按钮，重试成功后继续。离桌不受影响。不再有托管、熔断、托管计数。

★ 教练调用：主动提醒失败不重试、不打断（本来就可以沉默），在教练栏显示一行灰字“这次没连上”；提问失败在回答处显示「重试」；复盘失败在复盘卡上显示「重试」。

★ 入座前置条件：没有配置对手模型时不能开桌（大厅入座按钮置灰并引导去设置）；教练局还需要教练模型。README 中“不配置也能用本地引擎打牌”一并删除。

删除：`decide()`、角色 `profile`、设置 `engine`、设置页“本桌托管次数”、牌桌熔断横幅。

### D4 规则引擎（U2、U4）

用户的判断成立：JS/TS 没有热门的德扑桌引擎，热门的都是只比牌型大小的评估库；规则最严谨的 PokerKit 是 Python。实测（`note.md`、`evidence/research/`）：

| 选项 | 说明 |
| --- | --- |
| ★ A 保留自研引擎并修规则 | 修“短码不完整全下后重开加注”和“零头归属”两处；补一组规则用例（不完整加注、单挑、边池、未跟注退还、零头）和随机压测（筹码守恒、每手能结束、合法动作不被拒）。引擎 150 行、已有 239 行测试，改动小，无外部风险 |
| B 换 `@pokertools/engine` | 规则最全，1.0.20 实测 2.5 万手无误；但 2025-11 才发布、单作者、6 star，1.0.9 在库内出现筹码守恒崩溃；要改写 runner 与 view 对状态的读取（不可变状态、座位数组含空位、英文牌型名、全下后一次发完公共牌） |
| C `poker-ts` | 最老牌的 TS 桌引擎，但实测有同一处规则错误，不推荐 |

A 下仍保留 `@pokertools/engine` 作为测试依赖的想法不采纳：两边洗牌与座位无法对齐，做差分测试成本高于收益。

### D5 教练作为对局类型（U3）

★ 大厅“对局类型”二选一：教练局 / 自由局（教学牌局 = 教练局 + 每步必提醒）。类型在入座时定下，本桌不可改。

| | 教练局 | 自由局 |
| --- | --- | --- |
| 右侧教练栏 | 有：概率面板、主动提醒与暂停、提问、每手复盘卡 | 无，牌桌更宽 |
| 一手结束 | 所有人的底牌都亮出（弃牌者的牌半透明并标“已弃牌”） | 只亮摊牌的牌 |
| 手牌记录 | 存全部底牌，回放中显示 | 与现在相同 |
| 自动下一手 | 9 秒（留时间看复盘） | 4.5 秒 |

教练栏里仍可随时改的：人设、讲解深度、硬核模式（只影响提示词或显示，不牵涉流程）。“每手复盘”不再单独开关，教练局总是复盘。

是否更简单：现状下中途开关本身只是一处判断，不算复杂；但本轮新增的“亮弃牌”“每手复盘”“手牌记录是否含全部底牌”都要回答“这一手开始时教练开着吗、中途关了怎么办”。类型在入座时固定，一手要么是教练手要么不是，这些分支都不存在；全局设置 `coachOn` 也随之删除，变成牌桌属性。

信息隔离：亮出弃牌只在一手结束后发给玩家界面与教练；对手的“公开结果”仍只含摊牌亮出的牌。★ 教练复盘可以用这些牌（“你弃掉时对手其实是 A♠ K♠”），因为此时玩家也看得到。

### D6 自建对手与四项倾向

v2 设计稿新增自建、编辑、删除（可恢复）对手。★ 实现；四项倾向（紧度、攻击性、诈唬、跟注倾向）只服务本地引擎，★ 删除条与滑杆，性格完全由提示词描述。可选替代：保留滑杆并把数值翻译成一句话写进提示词。

存储：`river_personas` 从“内置角色提示词覆盖”扩为完整角色表（内置角色的覆盖、自建角色、已删除标记）；对手印象（D2）按角色 id 存。

### D7 教练调用同样收敛为单次（与 U1 同理，AI 建议）

★ 主动提醒：局面与本地计算写进输入，只开放 `hint` / `pause_game`，`maxSteps: 1`，不调用工具即沉默。
★ 复盘：一次调用，工具 `recap({ headline, good, improve, tip, note? })` 产出复盘卡四段；`note` 追加到“学员档案”（与 D2 A 同一机制，代码维护）。回放页“让教练复盘这一手”用同一调用，结果结构化存库；旧的纯文本复盘按原文显示。
★ 提问：保留流式输出与本桌对话历史（Mastra thread `coach:<tableId>`），局面写进输入，不开放工具。

### D8 用量与花费

记 Mastra `totalUsage` 的真实 token，按用途（对手决策、教练提醒、教练问答、每手复盘）和每手累计，存 SQLite。★ 设置页每个角色模型旁可选填“输入 / 输出单价（每百万 token，美元）”；填了显示花费，没填只显示 token，顶栏胶囊显示“本桌 x token”。

### D9 自动更新（U5）

结论：electron-builder 自带的 `electron-updater` 可以直接用 GitHub Releases，不需要自建服务器（与 Tauri 一样读 Release 里的元数据文件）。限制在 macOS：Electron 的 macOS 自动更新（Squirrel.Mac）要求应用有正式的 Developer ID 签名，现在的 ad-hoc 签名装不上更新；Tauri 用自己的密钥校验更新包，所以不受这条限制。

| 平台 | 可做到 |
| --- | --- |
| Windows（NSIS） | 后台下载，退出时安装（未签名，SmartScreen 提示照旧） |
| Linux（AppImage） | 同上 |
| macOS（ad-hoc） | ★ 只做“检查更新 + 提示下载”：发现新版本时弹提示，点“下载”打开 Release 页面，手动拖入安装 |
| macOS（Developer ID，年费 99 美元） | 全自动；需要证书、公证、CI 配置密钥 |

还需要：Release 不能停在草稿（electron-updater 看不到草稿），CI 要额外上传 `latest*.yml` 与 `.blockmap`，macOS 目标加 `zip`；仓库若为私有，客户端需要 token 才能读 Release，不可接受——需确认 `reflux-studio/river` 是公开仓库。

## 4. 进程与模块变化（摘要）

```
TableRunner（主进程）
  轮到对手 ─► 拼局面文本 ─► opponent.act 一次调用 ─┬─ ok ─► apply + 公屏(行动+发言) + 印象追加
                                                    └─ 失败 ×3 ─► stalled（等「重试」）
  轮到玩家 ─► [教练局] coach.hint 一次调用（可沉默）
  一手结束 ─► 落库 ─► [教练局] 亮全部底牌 + coach.recap 一次调用 ─► 复盘卡
Renderer
  公屏只读 · 教练栏仅教练局 · 桌面外观/动效 · 自建对手 · 用量统计 · 更新提示
```

删除的模块：`agents/leak.ts`、`table/chat.ts`、`agents/queue.ts` 的抢占逻辑中只为闲聊存在的部分（保留串行队列给教练问答与复盘）、`views.ts` 中只供工具使用的查询接口。

## 5. 风险

| 风险 | 处理 |
| --- | --- |
| 小模型不调用 `act` 或参数非法 | 非法动作由引擎纠正（与现在相同）；不调用算失败走重试；多次失败时横幅提示换模型 |
| 去掉会话历史后对手“失忆” | 印象列表 + 最近 3 手摘要；用户可选 D2 B |
| 单次调用延迟仍高（6 人桌一圈） | 局面直接给出，省掉读取工具的往返；思考速度只控制最短停顿 |
| 自建对手删除后旧手牌记录引用失效 | 手牌记录本来就存名字；印象随角色删除一并删除 |
| macOS 用户得不到自动更新 | 提示下载；是否购买 Developer ID 由用户决定 |
