## 2. 对手：每回合一次调用（U1、A1、A2）

- 轮到对手：TableRunner 把该座位视角写进输入（阶段、底牌、公共牌、底池、需跟注、可选行动与加注范围、各座位公开状态、本手行动、最近 8 条公屏、本地胜率参考、本桌最近 3 手公开结果摘要、该角色的长期记忆文档）。只开放工具 `act({ action, to?, say?, note? })`，`to` 为加注到的总额；`toolChoice: 'required'`（提供方不支持时 `auto`），`maxSteps: 1`；同一步多次 `act` 只取第一次。
- 发言规则（替换现提示词中禁止提点数的一句）：想说就在 `say` 里说一句，不超过 20 字，符合人设；可以虚张声势、谈论牌面，但不要如实报出自己的底牌；不说就留空。代码只截断到 40 字防止撑坏气泡。
- 长期记忆（A2）：Mastra 的开箱方案不合适——working memory 要额外一次工具调用才能更新；Observational Memory 靠后台 Observer/Reflector 额外调用模型，并且默认先保留约 3 万 token 的原始历史才开始压缩，与“省 token”相反（依据 `@mastra/memory` 1.31 包内文档 `docs-memory-observational-memory.md`、`reference-memory-observational-memory.md`）。因此自己维护：`act` 的可选 `note`（≤30 字，对某人的新观察或自己心情）追加到该角色的记忆文档，每角色只留最近 10 条，存 SQLite，跨桌共享。
- 随之不再需要 Mastra Memory：对手不带会话历史；教练问答的本桌对话历史由 TableRunner 保存并在每次调用时传入。去掉 `@mastra/memory`、`@mastra/libsql` 依赖和 Mastra 的存储表，上一轮为业务层与 Mastra 并发写同一库而做的 BUSY 重建与串行设计（note T3 结论）也随之不再需要。
- 重试（A1）：用 Mastra 自带的模型调用重试（默认 2 次，1 秒起指数退避，遵守 `Retry-After`，401/404 等不可重试错误直接失败；`@mastra/core` dist `agent-DwtTO5Px.js` 第 24963–24968、25135 行），不自己再写重试。每次决策整体限时 45 秒（含重试）。
- 失败即停下（`stalled`）：Mastra 重试后仍失败、超时、模型没有调用 `act`、模型未配置或密钥不可用，都直接停下。操作区上方显示“阿狸 的模型调用失败：<原因>”，按钮「重试」（再发起一次调用，读最新配置）与「去设置」。停下时离桌或退出：本手作废，所有人筹码恢复到本手开始时，再按离桌结算。
- 只在自己回合说话：赢家不发言；取消公屏回应与玩家发言。思考速度改为“最短显示时长”：调用返回太快时补足到 0.4/0.9/1.5 秒再落子。

删除：`view_table`、`estimate_equity`、`read_chat`、`hand_history`、`say` 工具；`chatReply`、`pickResponders`、冷却、`winnerSpeech`；IPC `chat.send`；`agents/leak.ts`、`table/chat.ts`、`agents/queue.ts`；消息的 `triggers`、`replyTo`、`autopilot`；角色的 `talk`、`lines`、`profile`；`LINES`；`decide()`；设置 `engine`、熔断、托管计数与横幅。

## 3. 教练与对局类型（U3、A3、A4）

大厅“对局类型”分段控件：教练局 / 自由局，替换大厅“教练”开关；全局设置 `coachOn` 删除。教学牌局是教练局的一种（固定 3 人桌、每步必提醒），入口保持在大厅右侧卡片和引导页末页。

| | 教练局 | 自由局 |
| --- | --- | --- |
| 右栏 | 概率面板、教练提醒、提问、复盘卡 | 只有概率面板 |
| 轮到玩家 | 先等教练看完（见下），再解锁操作 | 直接操作 |
| 一手结束 | 所有人底牌亮出，弃牌者的牌半透明并标“已弃牌”（弃牌结束的手也亮）；教练复盘 | 只亮摊牌的牌 |
| 下一手 | 手动（按钮或 N/空格）；复盘结束或失败后才可点 | 手动 |

A4 的做法（“每一步先听教练说”）：
- 轮到玩家时操作区显示“教练正在看牌…”并锁定；教练返回后解锁。教练要么沉默，要么给一句提醒（工具 `hint`，`maxSteps: 1`，局面写进输入）。操作本来就被锁着，原来的“暂停牌局”工具与暂停遮罩不再需要，删除。
- 一手结束先出复盘卡（工具 `recap({ headline, good, improve, tip })`），复盘结束后“下一手”才可点。
- 提问只在教练空闲时可发（教练看牌或复盘时输入框禁用），发出后等回答完成。
- 这样同一时刻最多只有一个教练调用，不存在晚到的提醒、复盘挡住下一手提醒、提问抢占提醒这些情况；原来的串行队列与抢占逻辑整体删除。
- 教练失败：提醒失败显示一行灰字“教练这次没连上”并解锁；复盘失败在卡片上显示「重试」，同时允许直接下一手；提问失败在回答处显示「重试」。
- 离桌：在途的教练调用中止；未完成的复盘可在回放页重新发起。
- 教练的学员档案：`recap` 可带可选 `note`，与对手相同的记忆文档机制（存 `hero` 一份）。

教练栏里随时可改：人设、讲解深度、硬核模式。复盘可以使用亮出的弃牌；对手读到的只有公开结果。

取消自动下一手后，设置页“自动下一手”一并删除。

## 4. 规则引擎（A5）

保留自研，改写为 `poker-ts` 风格的 `Table` 类（`src/main/engine/`），规则按 §4.2 修正。

### 4.1 API

```ts
const t = new Table({ smallBlind: 50, bigBlind: 100 }, 6, rng)
t.sitDown(0, 10000)                 // 座位、买入
t.startHand()                       // 按钮自动轮转，发底牌，下盲注
while (t.isHandInProgress()) {
  while (t.isBettingRoundInProgress()) {
    const seat = t.playerToAct()
    const { actions, chipRange } = t.legalActions()   // 'fold'|'check'|'call'|'bet'|'raise'，chipRange 为下注/加注到的总额范围
    t.actionTaken(action, betSize)
  }
  t.endBettingRound()               // 收池、发下一街；全下后无人可行动时逐街调用即可发完
  if (t.areBettingRoundsCompleted()) t.showdown()
}
t.winners()                         // 每个底池的赢家、金额、牌型
```

读状态：`button()`、`seats()`（筹码、本轮下注、状态）、`holeCards()`、`communityCards()`、`roundOfBetting()`、`pots()`、`handLog()`（本手行动记录，供公屏与回放）。牌仍用 `'As'`、`'Td'` 字符串；随机数可注入，测试可复现。

`endBettingRound` 由 TableRunner 调用，天然就是“一街一街地翻牌”的节拍点，界面的发牌、翻牌动效和全下后逐街发完都挂在这里。

### 4.2 规则修正（相对原型 `poker.js`）

| 问题 | 修正 |
| --- | --- |
| 短码不完整全下后，已行动者仍可再加注 | 不完整加注不重开已行动者的加注权；多次不完整全下累计达到一个完整加注额时重开；`legalActions` 与 `actionTaken` 判定一致 |
| 平分底池余数全给座位靠前的赢家 | 从按钮左侧起逐枚分配 |
| 无人跟注的下注计入“赢得” | 未被跟注部分直接退回，赢得金额只算真正赢到的 |

测试：保留原型对照用例中与修正无关的部分；新增规则用例（不完整加注、单挑顺序、边池、未跟注退还、余数分配）与随机压测（筹码守恒、每手能结束、`legalActions` 给出的动作 `actionTaken` 都接受）。`evaluate`、`equity`、`outs` 沿用现实现。

## 5. 自建对手（v2 设计稿）

- 实现新建、编辑（名字、头像字、标签、简介、头像色、提示词）、删除、恢复内置、恢复默认；四项倾向删除。
- 角色表存 SQLite，经 IPC 下发；内置 8 个角色在代码里作为种子。自建角色 id 为 `c` + 随机串。
- 牌桌入座时保存角色快照，删除只影响下一桌；编辑提示词从下一次决策生效。
- 至少保留 1 个角色；删除时从大厅已选中移除；可用角色不够时大厅人数上限随之降低。教学牌局优先小白、禅师，被删时从可用角色补位。
- 删除角色时一并删除其记忆文档。

## 6. 用量与花费（A6）

- 现状核实：设置页的模型列表并不是连供应商接口拉的，而是 Mastra 包内自带的静态注册表 `provider-registry.json`（数据源是 models.dev），只有提供方和模型名，没有价格；“OpenAI 兼容接口”的模型需手填。
- 价格：models.dev 公开的 `https://models.dev/api.json` 按提供方和模型给出每百万 token 的输入、输出价格（公开文档所述；本会话网络策略拦截，未实测）。做法：应用启动时拉一次（失败则用上次缓存），按设置里的“提供方类型 + 模型 id”查价；查不到（如 OpenAI 兼容接口）只显示 token。不做手填单价。
- 记账：每次调用记 Mastra `totalUsage` 的输入、输出 token，按用途（对手决策、教练提醒、教练问答、复盘）与所属手牌累计，存 SQLite。超时或中止的调用记次数、token 未知。
- 显示：顶栏胶囊“本桌 $x”（无价格时“本桌 x token”）；统计页按设计稿的用量与花费区块（去掉“公屏对话”“本地引擎兜底”），保留清零、每手花费柱状图、回放副标题中的花费。

## 7. 新版本提示（U5）

- 不引入 `electron-updater`：启动时和每 6 小时请求一次 GitHub `releases/latest`（仓库公开，无需 token），版本高于当前时在大厅顶栏显示“新版本 x.y.z · 下载”，点击用系统浏览器打开 Release 页面。牌桌中不打扰。
- CI：从 tag 注入版本号（`extraMetadata.version`），Release 不再是草稿（或由用户手动发布，发布前客户端看不到）。
- 所有平台行为一致，不需要签名或安装器配合。

## 10. 一手的时序

```
startHand ─► 轮到对手 ─► act（Mastra 内部重试）─┬─ ok ─► 补足最短显示时长 ─► actionTaken ─► 公屏（行动+发言）─► 记忆追加
                                                 └─ 失败 ─► stalled ─►「重试」/「去设置」/ 离桌（本手作废）
          ─► 轮到玩家 ─► [教练局] 锁定 ─► hint（可沉默）─► 解锁 ─► 玩家行动
          ─► 本轮结束 ─► endBettingRound（翻牌动效）─► … ─► showdown
一手结束 ─► 落库 ─► [教练局] 亮全部底牌 ─► recap ─► 复盘卡 ─► 「下一手」可点
```

## 11. 风险

| 风险 | 处理 |
| --- | --- |
| 小模型不调用 `act` | 直接停下，横幅提示可重试或换模型 |
| 教练局每步多等几秒 | 这是 A4 的取舍；自由局不受影响 |
| models.dev 不可达或查不到价格 | 用缓存；仍没有就只显示 token |
| 去掉 Mastra Memory 后教练“不记得”跨桌对话 | 学员档案（记忆文档）跨桌保留；本桌对话历史照常 |
| 规则修正让原型对照测试失效 | 对照测试逐条标注修正项 |
