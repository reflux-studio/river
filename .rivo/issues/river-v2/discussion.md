# River v2：方案讨论快照（第 2 轮，含审阅 1 修订）

本文件记录讨论收敛出的做法，供用户确认。未经批准前不是最终 plan。调查依据见 `note.md`；第 1 轮审阅见 `reviews/design-1.md`（需修改，10 条，本轮逐条处理，对照见 §9）。

## 1. 原始请求

导入设计项目中的 `River v2.dc.html`（附 `poker.js`、`support.js`）并实现，走 Rivo 流程。用户同时提出（2026-09-24）：

| # | 用户原话要点 |
| --- | --- |
| U1 | 对手每回合只做一次 tool call，同时完成下注和发言；不在自己回合就不说话；取消自由发言；玩家也不发言（公屏只读）；不需要关键词泄牌过滤，诈唬说“我有三个 A”也不违规 |
| U2 | 不做本地托管引擎；出错自动重试，失败就停下，给手动恢复；调研现成德扑规则引擎 |
| U3 | 教练模式下，一手结束亮出已弃牌的手牌；教练模式做成“对局类型”，不在对局中开关 |
| U4 | 追问：找到的库只有 6 star，是不是没有热门引擎 |
| U5 | 引入自动更新；问依赖服务器还是只要 GitHub |

设计稿里仍有的公屏输入框、话痨档位、本地引擎兜底、泄牌过滤，以 U1/U2 为准删除。

## 3. 方案

### 3.1 对手：每回合一次调用（U1）

- 轮到对手：TableRunner 把该座位视角写进输入（阶段、底牌、公共牌、底池、需跟注、可选行动与加注范围、各座位公开状态、本手行动、最近 8 条公屏、Q6 的胜率行、Q1 的最近 3 手摘要）。只开放工具 `act({ action, to?, say?, note? })`：`to` 为加注到的总额（与现在相同）；`toolChoice: 'required'`（提供方不支持时 `auto`），`maxSteps: 1`。同一步多次调用 `act` 只取第一次（现有 `recordIntent` 已如此）。
- 发言规则（替换 `opponent.ts` 第 41 行的禁令）：“想说就在 `say` 里说一句，不超过 20 字，中文口语，符合人设；可以虚张声势、谈论牌面，但不要如实报出自己的底牌。不说就留空。”代码只截断到 40 字防止撑坏气泡。
- 只在自己回合说话：赢家不再发言；取消公屏回应、玩家发言。
- 思考速度：改为“最短显示时长”——调用前不再停顿，调用返回太快时补足到 0.4/0.9/1.5 秒再落子。

删除：`view_table`、`estimate_equity`、`read_chat`、`hand_history`、`say` 工具；`chatReply`、`pickResponders`、10 秒冷却、`winnerSpeech`；IPC `chat.send`；`agents/leak.ts`、`table/chat.ts`；消息的 `triggers`、`replyTo`、`autopilot` 字段；角色的 `talk`、`lines`、`profile`；`LINES`。

### 3.2 失败处理（U2；审阅 F1）

- 只保留一层重试：Mastra 调用设 `maxRetries: 0`，由 TableRunner 重试。对手决策每次 20 秒超时，最多 3 次，间隔 1 秒、3 秒，最坏约 64 秒后停下。
- 以下错误不重试、直接停下：鉴权失败（401/403）、模型或端点不存在（404）、未配置或密钥解密失败（`modelReady` 为 false）。其余错误、超时、模型没调用 `act` 都算可重试失败。`act` 参数不合法（如缺 `to`）不算失败，由引擎纠正（与现在相同）。
- 停下（牌桌状态 `stalled`）：操作区上方显示“阿狸 的模型调用失败：<原因>”，按钮「重试」；对不重试的错误另显示「去设置」。按一次「重试」就是完整一轮（最多 3 次）。停下期间可以去设置页换模型，重试时读取最新配置。
- 停下时离桌或退出应用：按 Q3。
- 教练：主动提醒失败不重试、不打断，在教练栏显示一行灰字“这次没连上”；提问失败在回答处显示「重试」；复盘失败在复盘卡上显示「重试」（离桌后可在回放页重试）。
- 入座前置条件：没配对手模型时，所有入座入口（大厅入座、大厅“教学牌局”、引导页最后一页“带我打一手”）都改为跳转设置页并提示“先配置对手模型”；教练局还要求教练模型，缺少时同样跳转。README 删去“不配置也能用本地引擎打牌”。
- 删除：`decide()`、设置 `engine`、熔断与托管计数、托管横幅、设置页“本桌托管次数”“最近一次调用”。

### 3.3 教练作为对局类型（U3；审阅 F2、F4）

大厅“对局类型”分段控件：教练局 / 自由局，替换大厅里的“教练”开关。教学牌局是教练局的一种（固定 3 人桌、每步必提醒），入口保持在大厅右侧卡片和引导页末页。类型在入座时定下，本桌不可改；全局设置 `coachOn` 删除。

| | 教练局 | 自由局（按 Q2 推荐 A） |
| --- | --- | --- |
| 右栏 | 概率面板、主动提醒与暂停、提问、每手复盘卡 | 概率面板、提问 |
| 一手结束 | 所有人底牌亮出，弃牌者的牌半透明并标“已弃牌”（弃牌结束的手也亮） | 只亮摊牌的牌 |
| 自动下一手 | 9 秒 | 4.5 秒 |

教练栏里随时可改：人设、讲解深度、硬核模式。“每手复盘”不单独开关，教练局总是复盘。

为什么固定更简单：中途开关本身只是一处判断；但“亮弃牌”“每手复盘”“手牌记录是否含全部底牌”都要回答“这一手开始时教练开着吗、中途关了怎么办”。类型固定后，一手要么是教练手要么不是，这些分支都不存在。

教练调用（AI 建议）：
- 主动提醒：局面与本地计算写进输入，只开放 `hint`、`pause_game`，`maxSteps: 1`，不调用即沉默。
- 复盘：一次调用，工具 `recap({ headline, good, improve, tip, note? })`；`note` 追加到“学员档案”（代码维护，同 Q1 A 的机制）。回放页“让教练复盘这一手”走同一调用。
- 提问：保留流式输出与本桌对话历史（Mastra thread `coach:<tableId>`），局面写进输入，不开放任何工具。教练不再使用 Mastra working memory。
- 队列：主动提醒与提问共用一个串行队列（与现在相同，提问抢占提醒）；复盘单独一个队列，不挡下一手的提醒。
- 离桌时复盘继续执行，结果写入该手的记录，回放页可见，也可重试。
- 复盘可以使用亮出的弃牌（此时玩家也看得到）；对手的公开结果与最近 3 手摘要只用摊牌亮出的牌。

### 3.4 规则引擎（U2、U4；审阅 F10）

JS/TS 没有热门的德扑桌引擎，热门的都是只比牌型大小的评估库；规则最严谨的 PokerKit 是 Python。实测：

| 选项 | 说明 |
| --- | --- |
| ★ A 保留自研引擎并修规则 | 修：不完整加注不重开已行动者的加注权（多次不完整全下累计达到一个完整加注额时重开）；`legal().canRaise` 与 `apply` 判定一致；平分余数从按钮左侧逐枚分配。补规则用例与随机压测（筹码守恒、每手能结束、合法动作不被拒）。`poker.ts` 与 `test/engine.test.ts` 中“须与原型一致”的约定改为“与原型一致，以下规则修正除外”，并列出修正项 |
| B `@pokertools/engine` | 规则最全，1.0.20 实测 2.5 万手无误；但 2025-11 首发、单作者、约 6 star，1.0.9 在库内出现筹码守恒崩溃；需改写 runner 与 view 对状态的读取 |
| C `poker-ts` | 最老牌的 TS 桌引擎，实测有同一处规则错误 |

### 3.5 自建对手（设计稿 v2；审阅 F6）

- 实现设计稿的新建、编辑（名字、头像字、标签、简介、头像色、提示词）、删除、恢复内置、恢复默认；按 Q5 处理四项倾向。
- 角色表改存 SQLite，经 IPC 下发给界面（不再从 `shared/personas.ts` 直接读常量；内置 8 个角色仍在代码里作为种子）。自建角色 id 为 `c` + 随机串。
- 牌桌在入座时保存角色快照（名字、标签、头像、提示词）：删除只影响下一桌；编辑提示词从下一次决策生效（与现在相同）。
- 至少保留 1 个角色；删除时从大厅已选中移除。可用角色少于所选人数减 1 时，大厅人数选项上限随之降低并提示。教学牌局优先用小白、禅师，被删时从可用角色中补位。
- 角色删除时一并删除其印象。

### 3.6 用量与花费（设计稿 v2；审阅 F8）

- 每次调用记 Mastra `totalUsage` 的输入、输出 token，按用途（对手决策、教练提醒、教练问答、每手复盘）累计，存 SQLite。
- 超时或中止的调用：调用次数加 1，token 记为未知；提供方不返回用量时同样。统计里未知部分显示“—”并注明次数。
- 计入哪一手：一手进行中的调用计入该手；复盘计入被复盘的那一手；一手结束后到下一手开始前的提问计入刚结束的那一手。
- 按 Q8 显示花费。顶栏胶囊：有单价显示“本桌 $x”，否则“本桌 x token”。保留设计稿的“清零”“自某日起”“平均每手”、回放副标题中的花费、每手花费柱状图。“清空记录”不清用量，用量只能用“清零”。

### 3.7 自动更新（U5；审阅 F7）

- 加入运行时依赖 `electron-updater`，`electron-builder.yml` 显式配置 `publish: { provider: github, owner: reflux-studio, repo: river }`。
- CI：从 tag 注入版本号（`extraMetadata.version`），上传 `latest*.yml` 与 `.blockmap`，macOS 目标增加 `zip`；Release 不再停在草稿（或由你手动发布，发布前客户端看不到）。
- 行为：启动时和每 6 小时检查一次。Windows、Linux 后台下载，大厅顶栏出现“新版本 x.y.z 已就绪 · 重启更新”，只在大厅可点，牌桌中不安装；未点则下次退出时安装（有桌时退出照旧先按离桌结算）。macOS 按 Q9。
- 更新提示的界面设计稿里没有，由 AI 按现有顶栏风格设计。
- 数据库迁移只前进，降级不支持。
- 依据：electron-builder 包内类型与源码核实了 GitHub provider、草稿不可见、私有仓库要 token、macOS 要 zip；“macOS 自动更新需要 Developer ID 签名”来自公开文档与 Squirrel.Mac 原理，本地未装 `electron-updater`，未从源码核实。

## 6. 一手的时序（摘要）

```
轮到对手 ─► 拼局面 ─► act（≤3 次）─┬─ ok ─► 补足最短显示时长 ─► apply ─► 公屏（行动+发言）─► 印象追加
                                    └─ 失败 ─► stalled ─►「重试」/「去设置」/ 离桌（Q3）
轮到玩家 ─► [教练局] hint/pause（可沉默，与提问同队列）
一手结束 ─► 落库 ─► [教练局] 亮全部底牌；recap（独立队列）─► 复盘卡；9 秒后下一手（Q4）
```

## 7. 风险

| 风险 | 处理 |
| --- | --- |
| 小模型不调用 `act` | 算可重试失败；三次仍失败就停下，横幅提示可换模型 |
| 去掉会话历史后对手“失忆” | 印象列表 + 最近 3 手摘要；可选 Q1 B |
| 6 人桌一圈等待长 | 局面直接给出，省掉读取工具的往返 |
| 引擎规则修正与原型对照测试冲突 | 对照测试逐条标注修正项 |
| 自建对手删除影响在座牌桌 | 牌桌持入座快照 |
| macOS 用户拿不到自动更新 | 提示下载；Q9 B 可升级 |

## 8. 不做

多人联机、账户与云同步、深色模式、代码签名（除非 Q9 选 B）。
