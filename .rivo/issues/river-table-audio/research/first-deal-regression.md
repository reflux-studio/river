# 首手发牌与音画节奏缺陷

负责人：Codex；日期：2026-11-01。来源：用户本聊天实测反馈及当前未提交实现。

用户报告第一手有发牌声却没有发牌动画，后续手有动画，且声音节奏过快。已定位：共享 useTableFx 首次没有上一帧时直接返回，只在后续 handNo 改变时启动发牌；音频由独立 IPC 事件即时播放，早于 React 的 DOM 提交。原来的 85ms 逐张间隔又使多个纸牌采样密集重叠。

修复采用显式实时 dealId 和 layout effect：DOM 就绪时启动动画并回调开始声音，共用纯 timing 模块的 170ms 逐张间隔、500ms 单张飞行。恢复快照、回到牌桌和重复渲染不生成 dealId，避免历史重放；视觉特效关闭时仍触发声音回调。后台没有牌桌 DOM 时继续即时播放声音。

进一步静态核对：6 人桌最后一张在 1870ms 起飞、2370ms 落定，而最快 AI 在 400ms 即可能行动并移除弃牌卡 DOM。因此牌局推进也需等待本手的发牌阶段完成，玩家操作、AI 和教练均在阶段后启动；旧手定时器仍由离桌/换手生命周期取消。

主代理回归先失败：169ms 时已有 2 段发牌声（预期仅 1 段），首手声音在视觉回调前已播放。修复后音频及 renderer 同步 4 文件 21 项通过。共享 UI 执行者首轮 4 项行为失败后实现，最终 13 项通过。最终集成与运行证据另记，不沿用上轮通过结论证明本轮修复。
