# 统一牌桌 Agent 与本地数值：技术方案

讨论过程与各轮决定：`discussion.md`；审阅记录：`reviews/design-1..4.md`；重要选择：`adr/006-unified-table-agent-context.md`。

## 需求与本期范围

**为什么做**：用户实际游玩时发现以下问题：

- 教练把玩家的位置说错（玩家在枪口，教练说成大盲），对手也会说错自己的位置。
- 教练对话接不上上文，讲解失败后没有重试入口。
- 复盘只盯着玩家的决策，不参考对手的倾向。
- 对手打法前后不连贯，像在乱打。
- 本地「规则引擎」算出的数值口径混乱，还被写进了提示词，把模型带偏。

用户的判断：对手和教练应该共用同一套上下文管理，教练只是一个没有操作权、只给建议的 Agent。模型用的是 DeepSeek，能力足够，提示词不用把模型当傻子。

**本期功能点**：

1. **局面文本对齐人类视角**：人类玩家在牌桌上能看到的，Agent 都要知道（用户提出的原则）。包括按行动顺序列出座位并标注位置、当前牌型、桌型与盲注、本手累计投入；对手视角里玩家不再被写成「你」。
2. **统一 Agent 上下文**：对手和教练各有一条本桌 thread。本手的观察完整保留，往手压缩成摘要，保留最近 5 手。出牌、复盘、赛后发言在 thread 里都记成真实的工具调用。
3. **对手出牌带 `think`**：写进自己的 thread，不公开。
4. **赛后发言**：一手结束后，入过池的对手各发言一次，不阻塞下一手。教练局的复盘仍然阻塞下一手，复盘时结合各家倾向。
5. **教练讲解和提问被打断**：界面上已经显示的文字写入 thread，并加标记。讲解失败后可以重试。
6. **本地数值**：删除「规则建议」和「跟注 ±EV」；胜率改为 2500 次模拟，并改名；出路改口径，并改名为「改进牌」。胜率和改进牌都不再写进提示词。
7. **加注额可以直接输入**。
8. **Windows 顶栏**：去掉系统标题栏和默认菜单，窗口按钮叠加在应用顶栏上（用户在本期中途追加的独立 UX 项）。

**明确不做**：

- 按对手的行动推测范围再算胜率：这是模型该做的推理。
- 往手用模型做总结：压缩由代码完成。
- thread 持久化：离桌即清空。
- 针对 Anthropic 等提供方做「按工具渲染历史」：用户只用 DeepSeek，见「待决问题」。
- 提示词里加打法指引。

**验收**：「验证与发布」一节里的场景全部通过。

## 现状与总体方案

与本次改动相关的现状：

- `table/text.ts` 的 `situation(t, seats, seat, o)` 是对手和教练共用的局面文本，按视角裁剪底牌。本期之前的版本不含位置信息（位置修复已在工作区完成，未提交）。
- 对手（`agents/opponent.ts`）每次决策都是独立调用，不带历史。system 是人设和长期印象；user 是局面、最近 8 条公屏、最近 3 手的公开结果和胜率。强制调用 `act` 工具；提供方不支持强制调用时改为 auto。
- 教练（`agents/coach.ts`）：讲解不带历史；提问带最近若干轮问答；复盘只看本手摘要。三者的 system 各不相同。
- `llm.ts` 的 `callModel` 每次新建一个无记忆的 Mastra Agent（ADR-004），`Msg` 只能表示文本。
- 用户本地的 DeepSeek 提供方 `supports_required = 0`，模型是 `deepseek-flash`。所以对手和复盘实际走的都是 auto 模式。

总体方案：

```
                 TableRunner（事件源，牌局与 thread 的唯一写入方）
                        │ 按视角裁剪的观察（situation / 公开结果 / 玩家视角摘要）
     ┌──────────────────┼────────────────────┐
     ▼                  ▼                    ▼
  对手 Thread ×N                          教练 Thread
  视角 = 自己的座位                        视角 = 玩家座位（不占座）
  工具：act（出牌）、talk（赛后发言）        流式讲解、回答；工具：recap
     └── 同一个 Thread 类：往手摘要 + 本手消息组；callModel 接收完整消息 ──┘
```

对手和教练的差别只体现在三处：system 文案（人设）、观察的视角、可用的工具。thread 的数据结构、写入契约和压缩规则完全一样。ADR-006 记录了这一决定：它修订 ADR-004 中「对手不带会话历史」这一条，存储部分不变。

## 局面文本：人类玩家能看到的，Agent 都要知道

**原则**（用户提出）：Agent 的观察应当等于同一视角下的人类玩家在牌桌界面上能看到的全部信息，不多也不少。对手等同于坐在那个座位上的人类玩家；教练等同于坐在玩家背后的人。今后界面上新增可见信息时，要同步加进观察。

下面按牌桌界面（`table/view.ts`、`TopBar`、公屏）逐项对照：

| 人类可见 | 观察里的位置 | 本期变化 |
|---|---|---|
| 桌型、盲注、人数（顶栏「无限注 · 50/100 · 6 人桌」） | `situation` 第一行 | 新增 |
| 第几手、当前街 | `situation` 第一行 | 已有 |
| 自己的底牌、当前牌型 | 视角行 | 牌型新增 |
| 公共牌、底池、需跟注、可选行动与加注范围 | `situation` | 所需胜率新增 |
| 各座位：名字、风格标签、位置（按钮、小盲、大盲）、筹码、本轮已下 | 座位行 | 位置已在工作区实现；修正：对手视角里玩家写「玩家」（玩家座位的内部名字是「你」，此前被原样写给了对手，对手会把玩家的行动当成自己的） |
| 各座位本手累计投入 | 座位行「本手共投入 X（含本轮）」 | 新增 |
| 各座位状态：已弃牌、已全下 | 座位行 | 已有 |
| 本手每一步行动和金额 | 「本手行动」 | 已有 |
| 公屏发言和气泡 | 上次观察之后的新发言（只取 `kind === 'msg'`，不含自己的，最多 8 条；夹带公屏的「第 N 手」分隔与重新买入，final-1 F1）；对手和教练规则相同 | 改为增量；行动已经在「本手行动」里，不重复 |
| 往手：摊牌亮出的牌、赢家和牌型、各家行动 | 往手回顾（`summary`） | 新增 |
| 教练局一手结束时亮出的全部底牌 | 只给教练（`heroHandSummary`） | 已有 |

另有两类信息的处理：

- **可推导的精确事实**：位置名、当前牌型、本手累计投入、所需胜率。人类可以从桌面上推算出来，这里直接算好给出，避免模型算错。
- **不给**：界面上没有的东西，包括他人的底牌；以及面板上给人类的辅助估算（随机牌胜率、改进牌），它们不是牌桌事实。

**说明**：
- 往手回顾只保留最近 5 手，这是为了控制上下文长度而有意截断的；人类能翻看更早的公屏。
- 筹码为 0 的对手会在下一手开始前自动重新买入，玩家筹码为 0 时不会开始下一手，所以牌局中不会出现「已出局」的座位，不需要额外列出。

## 位置与当前牌型

`positions(t)` 已在工作区实现：从小盲开始，按行动顺序排列本手的在座者（弃牌的人仍然占着位置），位置名如下表。

| 在座者 | 位置名 |
|---|---|
| 按钮 | 按钮；单挑时是「按钮/小盲」 |
| 小盲、大盲 | 小盲、大盲 |
| 大盲之后的第一位 | 枪口 |
| 按钮之前的最后一位（中间有至少两人时） | 关煞 |
| 其余 | 中位 |

`situation()` 的输出改为：

```
无限注 · 盲注 50/100 · 6 人桌；第 12 手，阶段：翻牌前
你的位置：枪口；底牌：5♠ 9♦；当前牌型：高牌
公共牌：无
底池：150；需跟注：100；所需胜率（底池赔率）：40.0%；筹码：38,200
可选行动：fold（弃牌）/ call（跟注 100）/ raise（加注到总额 200~38,200）
座位（按行动顺序，小盲起、按钮收尾）：
- 老K（小盲，紧凶）：筹码 9,600，本轮已下 50，本手共投入 50（含本轮）
- …
本手行动：…
```

- 当前牌型用 `handName(底牌 + 公共牌)`，只用到观察者自己的底牌，不涉及信息隔离。
- 所需胜率只在需跟注大于 0 时出现。
- 不再有「参考：胜率约 x%」这一行，也不再有「本地计算：…」这一附加段。
- 落库记录 `HandPlayer.pos?: string` 已经加上（旧记录没有这个字段）。`heroHandSummary` 会写出一行「位置：…」。

## 统一 Agent 上下文

### 数据结构

新模块 `src/main/agents/thread.ts`：

| 字段 | 类型 | 含义 |
|---|---|---|
| `past` | `string[]` | 往手摘要，每手一条，最多保留 5 条 |
| `hand` | `number \| null` | `groups` 属于第几手 |
| `groups` | `Group[]` | 本手已写入的消息组，按写入顺序 |
| `digest` | `string[]` | 本手自己的动作摘要，压缩时使用 |
| `summary` | `string \| null` | runner 在一手结束后写入的本手结果摘要（按视角，见下） |
| `chatSeen` | `string \| null` | 上次成功观察时公屏最后一条消息的 id；「新发言」从它之后读起（对手和教练都用） |
| `lastSituation` | `string \| null` | 上次写入的局面文本；教练提问时与当前局面比较，不同才附上（仅教练使用） |

`Group` 是一次成功调用写入的 2 条或 3 条消息：

| 形态 | 消息 | 用于 |
|---|---|---|
| 文本组 | user 文本 → assistant 文本 | 教练讲解、教练回答 |
| 工具组 | user 文本 → assistant `tool-call` → tool `tool-result` | 对手 `act`、对手 `talk`、教练 `recap` |

`llm.ts` 的 `Msg` 扩展为：

```ts
type Msg =
  | { role: 'user'; content: string }
  | { role: 'assistant'; content: string | [{ type: 'tool-call'; toolCallId: string; toolName: string; input: unknown }] }
  | { role: 'tool'; content: [{ type: 'tool-result'; toolCallId: string; toolName: string; output: { type: 'json'; value: unknown } }] }
```

`callModel` 把这些消息原样传给 `agent.stream` / `agent.generate`。已用 mock 模型验证：Mastra 1.69.0 会把 `tool-call` 和 `tool-result` 原样传给模型。`toolCallId` 由 Thread 生成，格式是 `h<手号>-<序号>`，只要求在同一条 thread 内能配对。

### 渲染与惰性压缩

```ts
// 某个 Agent 本次调用前
messagesFor(hand, observation):
  if this.hand !== hand:            // 新一手里第一次被调用：压缩所有尚未压缩的往手
    if this.hand !== null: past.push(`[第 ${this.hand} 手] ${summary ?? ''}\n你本手：${digest.join('；') || '无'}`)
    past = past.slice(-5); groups = []; digest = []; summary = null; this.hand = hand
  msgs = groups.flat()
  first = past.length ? `【往手回顾】\n${past.join('\n')}\n\n` : ''
  return groups.length ? [...msgs, user(observation)] : [user(first + observation)]
```

- 往手回顾放在本手第一条 user 消息的开头，不单独成为一条消息。所以 thread 始终是「一组接一组」，不会出现连续两条同角色的消息。
- 同一个 Agent 如果某一手完全没被调用（例如大盲遇到全员弃牌），下一手被调用时才压缩。`summary` 如果没写入就留空。一个 Agent 同一时刻只保留一手未压缩的内容；runner 写 `summary` 时，如果手号已经变了，就先压缩再写入。
- **压缩即中止**：压缩第 N 手时，如果该 Agent 第 N 手的赛后发言还在进行，就先中止它。中止点有两个：该对手在新一手里第一次被调用前，以及 runner 写下一手 `summary` 触发的压缩。
- 渲染时，往手的 tool-call 不再保留原结构，只以摘要文本的形式出现在回顾里。

### 写入契约

- 只有调用成功才写入。一次调用写入一组：`push(observation, output, digest)`。
- 失败、超时、被中止、没调用工具，都不写入。例外：教练讲解或回答如果界面上已经显示了文字，按文本组写入，assistant 内容末尾加「（被打断）」。
- 重试会重新走完整一轮，因为失败的那一轮没写入，所以不会重复。
- 同一个 Agent 的调用必须串行：
  - 对手的 `act` 由 `loop()` 串行驱动；
  - `talk` 在该对手下一次 `act` 之前会被中止（见「赛后发言」）；
  - 教练的讲解、提问、复盘由 `coachBusy` 互斥。
- 返回结果先核对 runId，再核对 `thread.hand` 是否仍等于这次调用所属的手号，任一不符就丢弃，不写入。**不看牌桌当前的手号**：玩家点了下一手、该对手还没被调用时返回的赛后发言照常写入。

每个 Agent 的 `digest` 条目：

| 调用 | digest 条目 |
|---|---|
| act | `<街> <实际行动>（想：<think>）；说：<公屏显示的发言>`，没发言就省略「说」 |
| talk | `赛后说：<公屏显示的发言>`，没说就写「赛后没说话」 |
| 讲解 | `讲解：<前 60 字>` |
| 回答 | `答玩家：<前 60 字>` |
| recap | `复盘：<headline>；下次记住：<tip>` |

### 各 Agent 的 system 与观察

**对手 system**（固定模板，每次调用重新读取长期印象）：

```
你在一张 PvE 娱乐德州扑克桌上扮演「<名字>」。<人设 prompt>
按人设决策，但别做明显送钱的离谱决定。你只能看到自己的底牌和桌上的公开信息。
轮到你行动时调用 act：think 写一两句你的真实盘算（只有你自己看得到），action 为 fold/check/call/raise（无人下注时 raise 就是下注），raise 时 to 为总额；say 是说出口的话（不超过 20 字，符合人设，可以虚张声势，不要如实报底牌）；note 记对某位玩家的新观察或心情。
一手结束后如果请你说句赛后的话，调用 talk：可以复盘、口嗨、嘴硬甚至撒谎，符合人设就行；不想说 say 留空。
你之前记下的印象：…
```

`act` 的 schema 在现有字段前面加一个 `think: string (optional)`，其余字段和对 `action`、`to` 的宽松校验保持不变。`talk` 的 schema：

| 字段 | 类型 | 含义 |
|---|---|---|
| `say` | `string?` | 赛后说的话，不超过 30 字，空表示不说 |
| `note` | `string?` | 对某位玩家的新观察，不超过 30 字 |

**对手的观察**：

- 出牌时：`situation(t, seats, seat, { chat })`。其中 `chat` 是该对手上一次成功被调用之后的新发言（只取 `kind === 'msg'`），不含它自己的发言，最多 8 条。去掉原来的 `equity` 和「本桌最近几手」。
- 赛后时：本手的对手 `summary`，再加一句「请说一句赛后的话」。

**教练 system**（统一一份，每次调用重新读取学员档案）：

在现有的人设、立场、水平、格式要求之外，加上下面这段说明。讲解、提问、复盘各自的要求放在当次 user 消息里：

```
你会在三种时刻收到消息：轮到玩家决策时（请讲解）、玩家提问时（请回答）、一手结束后（请调用 recap 复盘，结合对手在最近几手表现出的倾向来评价玩家的决策，只看决策质量不以结果论英雄）。
```

**教练的观察**：

| 时刻 | user 消息 |
|---|---|
| 讲解 | 玩家视角的 `situation`，再加「现在轮到玩家决策。…150 字以内」（新手引导局）或「…80 字以内」 |
| 提问 | `[第 N 手 <街>] <问题>`，再加「一般不超过 150 字，除非玩家要求详细」；如果局面与 `lastSituation` 不同，前面附上新局面 |
| 复盘 | `heroHandSummary(rec)`，再加「这一手结束了，调用 recap 复盘」 |

`recap` 的 schema 不变。回放页的「让教练复盘」没有牌桌 thread：用同一份教练 system，user 里只放单手摘要。

### 往手摘要 `summary` 的内容

一手结束时，runner 按视角为每条 thread 写入 `summary`：

| Agent | 内容 | 来源 |
|---|---|---|
| 对手 | 盲注、各家位置、公开行动线（`logLines`）、公共牌、公开结果（摊牌亮出的牌、谁赢多少、自己的输赢） | `publicHandResult` 扩展位置和行动线；只含公开信息，不读 `holeAfter` |
| 教练 | 与复盘输入相同：`heroHandSummary(rec)` | 玩家视角；教练局亮出的全部底牌玩家也看得到 |

压缩后的一条往手记录是 `[第 N 手] <summary>` 加 `你本手：<digest>`。「本桌最近几手」删掉以后，这就是对手了解别人打法的来源。

### tool-result 内容

| 工具 | `output.value` |
|---|---|
| act | `{ 实际: "加注至 300", 公屏: "<截断后的发言>" }`，没发言时不写「公屏」 |
| talk | `{ 公屏: "<截断后的发言>" }`，没说时写 `{}` |
| recap | `{ ok: true }` |

## 赛后发言

- **谁发言**：本手入过池的对手，即主动投入过筹码（跟注、下注、加注，盲注不算），或者看到了翻牌的人。玩家和已离座的人不发言。
- **何时**：在 `onHandEnd` 里，完成落库记录、写入各 thread 的 `summary` 之后，逐个异步发起，不阻塞下一手，也不影响「下一手」按钮能否点击。
- **调用**：`callModel({ purpose: 'talk', tool: talk, messages: thread.messagesFor(...) })`。优先强制调用，不支持时用 auto；超时 20s，不自动重试。
- **中止**：每个对手有自己的 `talkCtrl`。它在「压缩即中止」的两个中止点（该对手新一手第一次被调用前、写下一手 `summary` 触发压缩时）以及离桌时 abort。中止后返回的结果丢弃。
- **成功时**：
  - 说了话：公屏推送一条 `msg`，文本以 `[第 N 手赛后]` 开头，发言截断到 40 字，同时显示气泡；
  - 写入 thread 的工具组；
  - `note` 立即写入 `river_memory`。
- **失败、没调用工具、被中止**：当作这次没发言。不写入 thread，不弹横幅，不停牌局，note 丢弃。
- 用量统计新增 `purpose: 'talk'`，要同时改 `shared/types.ts` 的 `Purpose`、`models/prices.ts` 的 `PURPOSES`、`pages/Stats.tsx` 的 `PURPOSE` 标签和颜色。

## 教练讲解与提问的打断、重试

- **讲解**：
  - 成功：写入文本组。
  - 被跳过或失败：如果 `entry.text` 不为空，写入文本组并加「（被打断）」；为空就不写。
  - 失败时界面显示错误信息，并提供「重试」。条件是仍然在同一个决策点（`spokenKey === heroKey` 且这个决策点仍然等玩家行动），并且 `coachBusy` 为空。重试时复用同一个条目，清空文字，决策点重新锁定。`CoachState.retry` 给出可以重试的条目 id，复盘失败时也用它。
- **提问**：成功时写入文本组；失败时如果已经显示了文字，按同样的规则写入。
- 重试讲解时，thread 里保留着上一次被打断的那半句，界面上显示的是新生成的内容。这一点接受。

以上已在工作区部分实现：讲解重试、`CoachState.retry`、`coach.retry → runner.retryCoach()`。原先的过渡字段 `history` 会被 Thread 取代。

## 本地数值

| 项 | 计算 | 面板 | 提示词 |
|---|---|---|---|
| 对随机牌胜率 | 蒙特卡洛 2500 次，对手按「还没弃牌的对手拿随机牌」计算 | 显示 | 不写 |
| 所需胜率（底池赔率） | 跟注额 ÷ (底池 + 跟注额) | 显示 | 写（`situation`） |
| 当前牌型 | `handName` | 显示 | 写（`situation`） |
| 改进牌 | 见下 | 显示，附「按牌型大类」 | 不写 |
| 规则建议 | — | 删除 | 删除 |
| 跟注 ±EV 文字、配色、进度条上的刻度线 | — | 删除 | — |

**改进牌**：只在翻牌、转牌时计算。

- 定义：`rel(牌) = 我的牌型大类 − 公共牌自身的牌型大类`。下一张牌 c 满足 `rel(加上 c 之后) > rel(现在)` 时算改进牌。
- 例：7♠7♦ 遇到 K♣9♥2♠，发出 K 不算，发出 7 算；A♥5♥ 遇到 K♥9♥2♠，共有 15 张改进牌。

**其他改动**：

- 2500 次模拟在 1 到 5 个对手时实测 64 到 105 ms。每个决策点只算一次（沿用现有按 key 的缓存）。
- 对手不再需要胜率，原先每次决策 150 次的模拟去掉。
- `Nums` 和 `TableView.nums` 去掉 `sugg`。

## 加注额输入

`ActionBar` 中间的数额从 `div` 改成 `input`：

| 操作 | 行为 |
|---|---|
| 输入 | 只改草稿，不影响已确认的加注额 |
| 回车或失焦 | 去掉千分位后解析；为空或不是数字时回退到原值；否则夹到最小加注到全下之间，写回加注额；回车后失焦 |
| Esc | 放弃草稿，失焦 |
| 不能加注 | 输入框禁用 |
| 进入新的决策点 | 草稿随加注额一起重置为默认值 |

回车只确认数额，不会直接加注。加注仍然按 R 或点按钮。`hotkeys.ts` 在输入框聚焦时不响应快捷键，这是预期行为。

## Windows 顶栏

现状：`src/main/index.ts` 创建窗口时用的是 `titleBarStyle: 'hiddenInset'` 和 `trafficLightPosition`，这两个选项只在 macOS 上生效。到了 Windows，会退回到系统标题栏，外加 Electron 默认的 File/Edit/View/Window 菜单。顶栏组件 `TopBar.tsx` 左侧固定留出 88px，这是给 macOS 红绿灯让位的，在 Windows 上就成了空白。

改法：

| 平台 | 窗口选项 | 顶栏留白 |
|---|---|---|
| macOS | 不变：`titleBarStyle: 'hiddenInset'`、`trafficLightPosition` | 左侧 88px，不变 |
| Windows、Linux | `titleBarStyle: 'hidden'`；`titleBarOverlay: { color: '#f7f7f5', symbolColor: '#1d1d1f', height: 52 }`（颜色与 CSS 变量 `--topbar` 同步修改）；打包版（`app.isPackaged`）才执行 `Menu.setApplicationMenu(null)`，开发时保留菜单里的刷新和 DevTools | 左侧 16px；右侧 `padding-right: calc(100vw - env(titlebar-area-x, 0px) - env(titlebar-area-width, 100vw) + 16px)`，按实际按钮宽度自适应 |

- 渲染进程用 `navigator.userAgent` 是否包含 `Mac` 来判断平台，不需要改 preload。
- 顶栏已经有 `-webkit-app-region: drag`，可以直接用来拖动窗口。
- 去掉菜单后，Windows 上输入框的复制、粘贴由 Chromium 原生处理，不受影响。开发环境保留菜单，所以刷新和 DevTools 快捷键不受影响。

## 验证与发布

**单元测试**：

- Thread：
  - 成功写入组的形状；
  - 失败或中止时不写入；
  - 被打断且有文字的讲解会写入并带标记；
  - 惰性压缩：跨手、跳过一手、`summary` 缺失；
  - 窗口只保留 5 手；
  - 渲染后第一条 user 带往手回顾，后面严格按组排列。
- 信息隔离：对手 thread 和往手摘要里不出现 `holeAfter`，摊牌亮出的牌可以出现；对手视角里「你」只指它自己，玩家写作「玩家」（`heroHandSummary` 里也统一写「玩家」）。
- 公屏：对手 A 的赛后发言会出现在 B 下一次观察的新发言里；讲解和提问时，教练也会附上新发言。
- 赛后发言：
  - 玩家点了下一手、该对手还没被调用时返回的发言照常写入；
  - runner 写下一手 `summary` 触发压缩时，在途的发言被中止；
  - 只有入过池的对手发言；
  - 该对手下一次 `act` 前在途的 talk 被中止，结果丢弃；
  - 失败时不停牌局；
  - 成功时写入公屏（带前缀）和 thread，note 落库。
- 对手历史以 tool-call 和 tool-result 的形式传给模型（mock 模型检查 prompt）。
- 改进牌（手牌 / 公共牌 → 结果）：
  - A♥5♥ / K♥9♥2♠ → 15 张（9 张红桃、3 张 A、3 张 5）
  - 8♠7♦ / 6♣5♥K♠ → 14 张（9、4 共 8 张，8、7 共 6 张）
  - A♥5♦ / K♥9♥2♠7♥ → 河牌红桃算改进
  - 2♣3♦ / K♥9♥5♥7♥ → 河牌红桃不算
  - 2♥3♦ / K♥9♥5♥7♥ → 河牌红桃不算
  - 7♠7♦ / 7♣K♥2♠ → 发出 K 算（葫芦）
  - 5♥5♦ / 9♣9♦2♠ → 发出 2 不算，发出 5 或 9 算
- 位置：已有 3 条测试。

**实机验证**（DeepSeek，`deepseek-flash`，auto 模式）：

1. 打 10 手自由局：对手同一手内的打法前后连贯，赛后发言能出现，而且和它的 think 对得上。
2. 教练局：复盘出来之后先提一个问题，再点下一手。这时历史里有 recap 的 tool-call，本次请求却不带工具，要确认请求成功。
3. 教练局：追问「你刚才说的…」，教练能接上自己的讲解；讲解中途点「不等了」再追问，教练能接上已经显示的半句。
4. 教练准确说出玩家的位置和当前牌型。
5. Windows 打包版：顶栏没有系统标题栏和菜单；最小化、最大化、关闭按钮可用，底色和顶栏一致；拖动顶栏能移动窗口；窗口缩到最小宽度 880 时，导航和右侧按钮不重叠。macOS 上顶栏不变。（没有 Windows 机器时，交由用户验证。）
6. 加注输入框：输入精确数额、超出范围、非法输入、Esc、快捷键。
7. 观察 `river_usage.cached`，只记录，不作为验收条件。

路径 2 或「赛后发言始终不出现」只要有一个失败，就在实施内把 thread 渲染改成「本次请求注册了哪个工具，对应记录才渲染成 tool-call，其余一律渲染成文本」（design-3 的 a 方案），其他契约不变。

**发布**：随下一个版本发布，没有数据迁移，也不需要额外配置。回滚就是回退版本；新增的 `pos` 字段和 `talk` 用量行对旧版本无害（已核实：旧版 `usageSummary` 只按固定的 `PURPOSES` 列表分组，`talk` 行只计入总量，不会让统计页出错）。
