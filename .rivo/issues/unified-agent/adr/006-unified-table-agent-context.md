# 006：对手与教练共用一套本桌 thread（修订 ADR-004 的「对手不带会话历史」）

状态：已接受（2026-09-25，用户在方案讨论中提出并确认）
日期：2026-09-25

## 背景与问题

按 ADR-004，对手每回合只做一次 act 调用，不带会话历史。教练的讲解、提问、复盘则各自拼接上下文。实际游玩中暴露出四个问题：

- 对手在同一手里打法前后不连贯，看不到自己上一步为什么加注。
- 教练的讲解和复盘不进历史，玩家追问时教练接不上。
- 想加「赛后发言」，但对手没有记得自己思路的地方。
- 两套上下文逻辑各写各的，行为不一致。

## 可行选项

| 选项 | 说明 |
|---|---|
| A. 维持现状，分别修补 | 对手加上「本手行动」提示，教练把讲解并入问答历史 |
| B. 统一 Thread：每个 Agent 一条本桌 thread，只追加；往手由代码压缩；工具产出存成 tool-call | 对手和教练的区别只剩人设、视角和工具 |
| C. 引入 Mastra Memory 管理会话 | 需要重新引入存储，与 ADR-004 相反 |

## 决定与理由

采用 B，理由如下：

- **符合用户的判断**：教练就是一个只给建议、没有操作权的 Agent。
- **一套机制同时解决几个问题**：对手打法的连贯性、教练接上文，赛后发言也有了现成的写入位置（发言和复盘是同一类事件）。
- **不引入存储**：thread 放在内存里，离桌清空，ADR-004 的存储决定不变。
- **工具产出存成真实的 tool-call**：用户的 DeepSeek 实测不支持强制调用工具，只能走 auto 模式。历史如果是纯文本，模型可能会模仿着直接回文字，不调用工具。

## 后果与重新考虑条件

- ADR-004 中「对手每回合一次 act、不带会话历史」这一条被本决定取代，其余条款不变。
- 如果本次请求不注册工具、历史里却有 tool-call，Anthropic 等提供方会拒绝请求。用户只用 DeepSeek，接受这个风险。实机验证中，如果 DeepSeek 也拒绝，或者将来要支持这类提供方，就改为「按本次请求注册的工具渲染历史」，也就是只把本次可用工具的记录渲染成 tool-call。
- token 用量随窗口（5 手）增长。缓存只是附带收益，不作为设计理由。
- 需要跨桌的长期上下文时，仍然使用 `river_memory` 里的短印象。要做语义检索时，按 ADR-004 的重新考虑条件处理。
