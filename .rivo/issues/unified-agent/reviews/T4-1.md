## 发现

### F1 · 中 · 「玩家本手没有决策点」的验证项没有测试

- **证据**：task T4「验证」有一条：「玩家这一手没有决策点时…复盘就是本手第一组，写入的 observation 要带【往手回顾】；之后在同一手提问，messages 的第一组以【往手回顾】开头」。`runner.test.ts`「教练 thread」组的 6 条测试都没有覆盖这个场景。第 4 条测的是下一手讲解，那时玩家有决策点。
- **后果**：这正是 plan 专门点名的易错点（observation 必须用带回顾的那条原文）。以后如果有人把 recap 的写入改成直接用 `heroHandSummary(...)` 原文，现有测试全部照样通过，但 thread 前缀会不一致，往手回顾也会丢失。
- **建议**：补一条测试。对手一律 `fold`，驱动到玩家本手没有触发 `coachSpeak`、而且手号大于 1 的那一手。断言 recap 的 messages 只有一条 user，以【往手回顾】开头；再提问一次，断言 `asks[0][0].content` 以【往手回顾】开头，`asks[0][1]` 是 recap 的 tool-call。我在 scratchpad 里写的临时测试就是这个思路，可以直接拿来改。

### F2 · 低 · 若干行为只有实现，测试区分不出对错

- **证据和后果**：
  - 「局面变了就附上」只测了反向（没变时不附）。如果实现改成「永远不附」，现有测试照样通过。
  - `chatSeen` 仅在写入成功后推进、成功后不重复附上旧发言：没有测试。第 5 条只断言新发言出现过，如果 `chatSeen` 从不推进也能通过；如果失败时也推进了，同样测不出来。
  - `lastSituation` 在失败时不推进：没有测试。
  - `heroHandSummary` 行动行写「玩家」而不是「你」：没有测试。
  - 提问失败但已有文字时写入「（被打断）」：只测了讲解那条路径。
- **建议**：至少补两条：「局面变了就附上」（玩家行动后提问，断言含「当前局面（玩家视角）」）；「新发言不重复」（同一段新发言在一次成功讲解之后，下一次提问的 observation 里不再出现）。`heroHandSummary` 的称呼在 engine/text 测试里加一行断言即可。

### F3 · 低 · 调用成功但文本为空时，会写入一条空的 assistant

- **证据**：`writeCoach` 只拦截 `!ok && !text`。`ok && text === ''` 会走 `pushText(…, '', '讲解：')`。
- **后果**：thread 里会留下一条 content 为空的 assistant 消息，部分 OpenAI 兼容提供方会拒绝这种历史，导致之后的每次教练调用都失败。另外 plan 的写入规则是「没文字不写」，这里与之不符。概率低，因为模型返回 ok 却一个字都没流出的情况很少，但一旦出现，影响会延续整手。
- **建议**：改成 `if (!text) return false`（空文本不管 ok 与否都不写）。

### F4 · 低 · 复盘提示丢了「不论输赢都要复盘」

- **证据**：原来 recap 的 system 是「现在是这一手结束后的复盘。不论输赢都要复盘，只看决策质量，不以结果论英雄。调用一次 recap 工具给出复盘。」现在的统一 system 只保留了「只看决策质量，不以结果论英雄」，user 里是「这一手结束了，调用 recap 复盘。」
- **后果**：这与 plan「教练 system」给出的原文一致，不算偏离方案。但原来那句「不论输赢都要复盘」是防止模型在赢钱时敷衍的约束，现在去掉了。影响小。
- **建议**：可以把 `SPEAK_ASK.recap` 改成「这一手结束了，不论输赢都调用 recap 复盘。」，只改 user 这一侧，不动 plan 定下的 system。

### F5 · 低 · 被打断的长文本，digest 会丢掉「（被打断）」标记

- **证据**：`digest = \`${kind}：${said.slice(0, 60)}\``，而 `said = text + '（被打断）'`。文本超过 60 字时，标记会被截掉。
- **后果**：压缩后的往手回顾里，这条讲解看起来像完整说完的。影响很小，因为压缩后只剩摘要。
- **建议**：`\`${kind}：${text.slice(0, 60)}${ok ? '' : '（被打断）'}\``。

### F6 · 提示 · `SPEAK_ASK` 里还放了 `recap`

- 名字和内容不符。可以改名为 `ASKS` 或 `COACH_TASK`，也可以不改。
