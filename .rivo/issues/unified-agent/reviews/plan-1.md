# 方案审阅 plan-1：统一牌桌 Agent 与本地数值（首轮）

- 对象：`.rivo/issues/unified-agent/plan.md`（工作区快照，327 行）
- 基线：`main` @ 3ba346c，另有未提交改动（runner/text/coach/types 等 9 个文件）
- 对照：`discussion.md` 第 1–5 轮决定，`reviews/design-1..4.md`，ADR-006、ADR-004，以及 `src/main/{agents,table,engine,models}`、`src/renderer/src/{components/table,pages/Stats.tsx}`、`test/` 现有代码
- 结论：**需修改（无阻塞，重要 2 条，建议 4 条）**

整体评价：plan 忠实落实了 discussion 各轮决定。F2/F4 等已被取代的旧条款（「一次一对」「拼成文本」「入座快照」「（没说话）」）都没有残留。分组规则、tool-result 内容、talk 的失败语义、加注输入框、实机验证的两条路径和失败后的回退方案都写清楚了。改进牌示例（A♥5♥ / K♥9♥2♠ 共 15 张）、回滚结论（旧版 `usageSummary` 按固定 `PURPOSES` 分组）、位置表与 `positions()` 的实现一致，都已核对。

需要修改的是两处与「往手」有关的共同契约。一是赛后发言的过期判定写法与 F1 的决定相反，二是往手摘要 `summary` 的内容没有定义。这两处不写清楚，实施者照字面去做，结果会和用户已经确认的行为不一致。

## 发现

### P1【重要】赛后发言的「过期丢弃」按手号核对，与 F1 的决定相反；另外漏了一个中止点

**位置**：「写入契约」最后一条（「返回结果按『runId、手号』核对，已经过期的结果丢弃」）；「赛后发言 · 中止」。

**证据**：

- discussion F1 定的是：talk 唯一的中止点是「该对手在新一手里第一次被调用」。赛后发言如果在这之前完成，要写进压缩摘要，「不会因为玩家点『下一手』就被提前丢弃」。N5 给赛后发言加「[第 N 手赛后]」前缀，也正是因为它可能在下一手里才出现在公屏上。
- 现有代码的过期判定是拿发起时的手号和 `t.handNumber()` 比（runner.ts 278：`t.handNumber() !== hand`）。实施者照「按 runId、手号核对」来写，自然会沿用这个写法。
- 下一手由玩家手动开始（`nextHand` 只由按钮或 rebuy 触发），DeepSeek 的 talk 一般要几秒。所以「玩家已点下一手、该对手还没轮到行动时 talk 返回」是常见路径，不是边缘情况。

**后果**：如果按桌面手号核对，这条路径上的赛后发言都会被丢弃。实机验收第 1 条「赛后发言能出现」在正常节奏下可能很少通过，还会被误判成 R1 所说的「DeepSeek 拒绝带 tool-call 历史的请求」，从而错误地触发 design-3 a 方案的回退。

**漏掉的中止点**：plan 写了「runner 写 summary 时，如果手号已经变了，就先压缩再写入」。有一种情况：第 N 手的 talk 还在途，第 N+1 手里该对手一次都没被调用（例如全员弃牌到它的大盲，一手只有几秒），`onHandEnd(N+1)` 写 summary 时会压缩第 N 手。这时 talk 返回，会写进一手已经压缩掉的内容，违背 F1「不存在压缩之后才到」。plan 列的中止点只有「下一次 act 之前、离桌」，不包括这一种。

**建议**：把 talk 的规则统一成一句：**thread 压缩第 N 手时（不论是 `messagesFor` 还是写 `summary` 触发的），中止该 Agent 在途的第 N 手 talk；talk 返回时按 runId 和 `thread.hand === N` 核对，不看桌面当前手号。** 单元测试补一条：「玩家已开始下一手、该对手还没行动时 talk 返回，发言照常上公屏、写入 thread，并进入下一次的压缩摘要。」

### P2【重要】往手摘要 `summary` 的内容没有定义；按现有函数去做，达不到已确认的压缩内容

**位置**：「数据结构」表的 `summary` 行（「runner 在一手结束后写入的本手结果摘要（按视角）」）；「渲染与惰性压缩」伪代码；「对手的观察 · 赛后时」。

**证据**：

- discussion A 节表格定的压缩内容是：**位置、行动线、结果、自己的想法与发言**。plan 的往手条目是 `summary + digest`。digest 只包含「自己的想法与发言」，所以位置、行动线、结果要全部来自 `summary`，而 plan 没有说 `summary` 由哪个函数生成、包含什么。
- 现有的两个候选函数都不满足：
  - `publicHandResult`（text.ts）只有公共牌、亮牌、赢家和自己的输赢，**没有位置，也没有行动线**。
  - `heroHandSummary` 有位置和行动线，但包含 `holeAfter`，不能给对手用。
- 这次删掉了对手观察里的「本桌最近几手」（原来就是 `publicHandResult`）。往手回顾因此成了对手了解其他人（包括玩家）打法倾向的唯一来源。

**后果**：

- 实施者如果给对手用 `publicHandResult`，对手的往手回顾里就看不到别人怎么打，只剩自己的行动。这削弱了本期「对手打法连贯、有依据」的目标，也和 A 节的决定不一致。
- 如果为了拿到行动线改用 `heroHandSummary`，就会泄露 `holeAfter`。验证项里虽然有信息隔离测试，但方案本身应该先把契约写对，而不是靠测试兜底。

**建议**：在 plan 里明确每个视角的 `summary`：

- 对手：位置、公开行动线、公开结果，只用公开信息。可以新增一个函数，或者扩展 `publicHandResult`。
- 教练：`heroHandSummary`。
- 顺带说明对手赛后发言的观察（目前是 `publicHandResult` + 一句提示）是否也用同一份文本。它在该对手弃牌之后的行动，目前在 thread 里看不到。

### P3【建议】Thread 缺少两个游标，「新公屏」和「局面变了」没有判定依据

**位置**：「对手的观察」（「该对手上一次被调用之后的新公屏」）；「教练的观察 · 提问」（「如果局面在上一次观察之后变了」）；「数据结构」表。

**证据与后果**：

- 这两条规则都需要每个 Agent 各记一个状态：上次读到的公屏位置，和上次观察对应的局面 key。
- 数据结构表里没有这两个字段，也没有说它们放在 runner 还是 Thread 里。
- 公屏最多保留 300 条（`MAX_CHAT`），超出时会从头截掉，所以用下标当游标会错位。
- 「变了」的判定没写，实施者可能拿整段文本比较，而文本里有筹码、底池等字段，逐字比较未必是想要的口径。

**建议**：在数据结构中加上这两项，例如 `chatSeen`（按消息 id 或时间戳记录）和 `lastKey`（`${手号}-${handLog.length}`），并写明「变了」指 `lastKey` 不同。

### P4【建议】两处提示词内容在迁移中被静默删改

**位置**：「教练的观察」表的提问行；「对手 system」模板。

**证据**：

- 现在的提问在 system 里带有「回答一般不超过 150 字，除非玩家要求详细」（coach.ts）。F3 定的是「讲解、问答、复盘的具体要求放在当次 user 消息里」，但 plan 的提问 user 消息只有 `[第 N 手 <街>] <问题>`，这条要求没有着落。
- 现在的对手 system 第一句有「按人设决策，但别做明显送钱的离谱决定」，plan 的新模板删掉了。「不加打法指引」是用户的方向，但删掉已有的一句并没有被明确讨论过。

**后果**：教练回答可能变长；对手在 auto 模式下可能出现更极端的送钱打法。实机验收看到后，也难以区分是模板改动导致的还是 thread 导致的。

**建议**：提问行补上字数要求。对手模板那一句，保留还是删除都写明，删除的话在 plan 里注明「属于打法指引，按用户意见去掉」。

### P5【建议】ADR-004 与知识文档的同步范围

- ADR-004（river-v2）的状态仍是「提议」，文中没有指向 ADR-006。plan 的影响面只写了更新 knowledge README，建议加一条：在 ADR-004 中注明「『对手不带会话历史』已被 ADR-006 取代」。
- `.rivo/knowledge/README.md` 的「Agent 运行规则」和信息隔离部分，描述的是旧的 Mastra Memory / AgentQueue / `leak.ts` 架构，与当前代码不符，比如仓库里没有 `leak.ts`。只改「与 Agent 上下文有关的描述」，会留下自相矛盾的一份文档。建议写明更新范围包括这两节；或者注明其余过时内容不在本期范围，另行处理。

### P6【建议】验证清单的两处小缺口

- 改进牌测试写的是「覆盖 design-2 表里的 7 个例子」，需要跳转链接才能知道测什么。建议把 7 个输入和期望值直接列在 plan 里，或者至少列出那几个边界例：公共牌四张同花、暗三遇公共牌成对、口袋对遇公共牌成对。
- 赛后发言的测试需要补上 P1 的两个场景：下一手已开始、该对手未行动时返回；以及写 `summary` 触发压缩时中止在途的 talk。

## 其他核对（无问题）

- 需求范围：7 个功能点、「明确不做」的 5 项都与 discussion 一致，没有采纳未经批准的 AI 建议。自由局没有教练、`river_memory` 不变、离桌清空，均已保留。
- 修订替换：F2「一次一对」「（没说话）」、F3「入座快照」、F4「拼成文本」都没有出现在 plan 中；R1–R4 已全部落入正文。
- Msg 与 Mastra：扩展后的 `Msg` 是 AI SDK ModelMessage 格式，design-3 已用 mock 模型验证可以透传；`callModel` 现有的按角色映射（llm.ts 86）需要改，plan 已写「原样传给」。
- 回滚：旧版 `usageSummary`（prices.ts 68–80）只按固定的 `PURPOSES` 分组，`talk` 行只计入总量，结论成立。
- 位置表与 `positions()`（text.ts）一致；`handName` 在翻牌前返回口袋对子、同花底牌或高牌，与示例相符。
- 影响面：`AgentDeps` 需要新增 talk 入口，plan 已在测试替身一项中覆盖；ProbPanel 的「跟注 ±EV」、刻度线、`sugg` 的删除点与 CoachPanel.tsx 16–44 对得上。
