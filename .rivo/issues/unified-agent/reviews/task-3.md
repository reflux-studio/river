## 发现

### V-1（重要）T1 没有修正对手视角把玩家也叫「你」

- **证据**：玩家座位的 `SeatInfo.name` 是 `'你'`（`runner.ts:112`）；`situation()` 的 `who()` 和 `logLines()` 在对手视角下直接用它（`text.ts:55/70`）。实跑从对手座位 1 看到的是「- 你（大盲）…」「- 你（按钮）…」和「你 大盲 100，你 跟注 100，…你 过牌」，玩家和对手自己都叫「你」。详见 plan-3 的 P3-1。
- **后果**：T1 完成后，对手的每次观察仍然分不清自己和玩家的行动，位置也会说错；T3 的 thread 会把这段错误文本逐组保留下来。T1 的验证只查「位置、牌型、所需胜率、不含胜率约」，不会发现。T3 已为 `opponentSummary` 专门定了「座位 0 写玩家」，同一个对手的局面文本和往手摘要称呼还会互相矛盾。
- **建议**：
  - T1 步骤 1 加一条：对手视角里座位 0 写「玩家」，座位行和「本手行动」都改（例如在 `situation()` 开头对 `you !== false` 的情况把 `seats[0]` 改名为「玩家」，与教练视角的现有写法对称）。
  - T1 验证加一条：对手视角的观察里，「你」只出现在它自己的座位行和它自己的行动上，玩家的行动写成「玩家 …」。
  - T4 顺带把 `heroHandSummary` 行动行里的「你」统一为「玩家」（`text.ts:123` 照抄了记录里的「你」），与同段的「玩家底牌」一致。

### V-2（重要）新公屏的过滤与 8 条上限会挤掉赛后发言；教练的公屏规则与 plan 不一致

- **证据**：
  - T3 第 179 行：新公屏 = `chatSeen` 之后、`kind !== 'sys'`、`from !== pid`，取最后 8 条。公屏里还有每一步行动的 `act` 条目（`runner.ts:296/322`），与「本手行动」和往手行动线重复。
  - 赛后发言在上一手结束时推送；新一手里轮到该对手之前，前面座位最多 5 条 `act` 排在它后面，「最后 8 条」会把较早的赛后发言截掉。
  - T4 第 266 行让教练也用 `chatSeen`，并且包含系统消息（每手至少有「第 N 手 · 翻牌前」、各街发牌、赢家），名额更紧；而 plan 数据结构表写 `chatSeen`「仅对手使用」，对照表写「玩家视角的最近公屏」。
  - T4 只在讲解时附新公屏；一手结束后的赛后发言，在复盘和提问时都看不到，要等下一次讲解。T4 也没写教练的 `chatSeen` 在什么时候推进（讲解成功？被打断写入时？）。
- **后果**：赛后发言是本期新功能，其他对手和教练多数时候看不到它；T3 验证只查公屏出现了前缀，不查其他 Agent 能否读到，所以测试不会发现。教练被问到对手说了什么时答不上来。
- **建议**：
  - T3 第 179 行改为只取 `kind === 'msg'`（行动已在「本手行动」和往手摘要里），8 条上限放在过滤之后。「重新买入」如果要给，单独保留这一种系统消息。
  - T4 第 266 行同样只取发言；写明教练的 `chatSeen` 在写入成功（含被打断写入）后推进；提问的观察也附上新公屏。plan 同步去掉「仅对手使用」。
  - T3 验证加一条：对手 A 的赛后发言出现在对手 B 下一手第一次决策的观察里（前面有多个座位先行动的情形）。

### V-3（建议）「已出局」座位在牌局中不可达，测试需要单独构造

- **证据**：`nextHand()`（`runner.ts:189-196`）开局前给筹码为 0 的对手自动重新买入，玩家筹码为 0 时不开下一手；引擎只在 `startHand()` 重算 `out`（`engine/table.ts:105`）。所以通过 runner 永远构造不出进行中带 `out` 座位的局面。
- **后果**：T1 第 101 行「有已出局座位时显示已出局」只能在 `Table` 上手工 `setStack(i, 0)` 后 `startHand()` 来测；实施者可能先在 runner 测试里找不到办法，浪费时间。这段代码本身也只为不可达状态服务。
- **建议**：按 plan-3 的 P3-3 删掉这一步和对应断言；如果保留，写明用引擎直接构造、放在 `text.ts` 的单元测试里。

### V-4（建议）U-5 建议的验证没有进 T4 清单

- **证据**：T4 验证（第 283–289 行）没有「玩家这一手没有决策点，复盘之后提问，thread 第一组含【往手回顾】」。第 287 行只覆盖「下一手第一次讲解」这条路径。
- **后果**：复盘成为本手第一组时，如果误用 runner 自己拼的 obs 写入，往手回顾会从 thread 里丢失，现有验证都能通过。
- **建议**：补这一条。

### V-5（建议）共同接口的注释与 T4 用法不一致

- **证据**：第 28 行 `chatSeen` 注释为「对手：上次观察时公屏最后一条消息 id」，T4 第 266 行教练也用它。
- **建议**：注释改为不分角色，或随 V-2 一起改。
