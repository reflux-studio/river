## 发现

### F1（低）新一手的「新发言」混入上一手的行动发言，而且没有手号

- **证据**：探针中，阿狸在第 3 手翻牌前的第一次观察，「新发言」里出现了「老K：过牌，老K跟了」。这是老K 在**第 2 手**河牌的过牌。可是同一段观察的「本手行动」里，老K 只下了小盲。
  - 原因是 `newChat` 从 `chatSeen` 之后读起，会带上上一手末尾别人边说话边行动的 `msg`。
  - 这类消息没有手号，而界面上用来分隔各手的 `sys` 消息「第 N 手 · 翻牌前」又被过滤掉了。
- **后果**：模型可能把上一手的「过牌」当成本手的行动。人类在公屏上能看到分隔行，Agent 看不到，这与「人类可见」原则有一点偏差。对手的发言一般带 `say`，这种情况在实际游玩中会经常出现。
- **建议**：`newChat` 取到的消息如果早于本手开始，就在前面标上「[第 N 手]」，或者干脆只保留本手的消息加赛后发言。最省事的做法是记下本手开始时公屏的位置，给在它之前的消息加前缀。

### F2（低）runner.ts 里有两个没用到的导入

- **证据**：`tsc --noUnusedLocals` 报出 `runner.ts:2 cardsText` 和 `runner.ts:16 logLines`。这两个在 HEAD 版本里就已经没用了，不是本期引入的；但本期改写了这一行 import，顺手就能删。
- **其他问询项**：
  - `publicHandResult` 现在只被 `opponentSummary` 调用，仍然导出，无害。
  - `logLines` 的唯一调用方是 `situation`。
  - `equity` 仍由 `equityFor` 使用，`equityFor` 只剩 `numsFor` 这一个调用方，`iters` 参数恒为 2500（可以内联，低）。
  - `Nums` 和 `TableView.nums` 的两处定义都去掉了 `sugg`，与界面一致。
  - 没有 `retryRecap`、`askHistory`、`results`、`sugg` 或 `extra` 的残留。

### F3（低）知识文档的依据链接指向不存在的目录

- **证据**：`.rivo/knowledge/README.md` 第 8 行和第 107–109 行链接到 `../archive/river-desktop/...`，但 `.rivo/archive/` 不存在，实际位置是 `.rivo/issues/river-desktop/`。
- **后果**：以后读者点这些链接会找不到文件。
- **建议**：改为 `../issues/river-desktop/`，或者等真正归档后再统一修改。

### F4（低）「未注册工具时 tool-call 历史照传」没有自动化测试

- **证据**：
  - `agents.test`「tool-call 与 tool-result 原样传给模型」只测了注册了 talk 的调用。
  - 复盘之后提问（历史里有 recap 的 tool-call，本次不带工具）只在 runner 层用替身测过，没有经过 `callModel` 和 mock 模型。
  - 知识文档写的「本次调用没注册工具时也照传」，依据是设计阶段的临时实验。
- **后果**：Mastra 升级后，如果它开始过滤或改写这类消息，不会有测试报警。
- **建议**：在 agents.test 加一条：用 `coachAsk` 带 recap 的工具组历史，断言 mock 的 prompt 里有 tool-call 和 tool-result，工具列表为空。

### F5（低）教练往手回顾里的手号重复

- **证据**：探针中显示为「[第 1 手] 第 1 手，盲注 50/100」。Thread 加了一次前缀，`heroHandSummary` 自己也以「第 N 手」开头。
- **后果**：只是多了几个 token，不影响理解。
- **建议**：可以不处理；要处理的话，教练的 `setSummary` 传入时去掉首段即可。
