### env(titlebar-area-*) 的回退

- mac 上根本不设置该 `style`，所以不会受影响。
- 非 mac 且 WCO 生效时：`x≈0`、`width = 窗口宽 − 按钮区宽`，结果为「按钮区宽 + 16px」，随系统按钮实际宽度自适应。
- 非 mac 但环境变量缺失时（例如全屏时 overlay 隐藏）：回退为 `100vw − 0 − 100vw + 16px = 16px`，与 mac 的 `pr-4` 相同，是正常值。

### 拖动区域与 no-drag 区域

- `header` 整条 `[-webkit-app-region:drag]`。
- 可交互元素都在 no-drag 容器内：`nav`（导航按钮）、右侧两套容器（牌桌：本桌花费按钮、离桌；非牌桌：更新按钮、筹码）。Logo 和中间 `flex-1` 空白留在拖动区。
- 右侧留白区域落在拖动区内，但被系统 overlay 覆盖，窗口按钮由系统处理，不冲突。

### 类型

- 条件展开里的 `'hiddenInset'`/`'hidden'` 字面量在 `BrowserWindowConstructorOptions` 上下文中能正确收窄，node 检查通过。

## 发现

### F-1（建议）overlay 高 52px 会盖住顶栏底边线的右端

- **证据**：`header` 为 `h-[52px] border-b`，在 border-box 下底边 1px 位于第 52 行像素；`titleBarOverlay.height` 也是 52，覆盖区域从顶部起 52px，包含这 1px。
- **后果**：Windows/Linux 上窗口按钮下方的一段底边线会被 overlay 的 `#f7f7f5` 盖掉，顶栏分割线在右端断开约一个按钮区宽度（Windows 约 138px）。纯视觉问题，不影响功能。
- **建议**：交给用户在 Windows 打包版验证时顺带看这一处；如果确实断开，把 `height` 改为 51（按钮区仍与顶栏内容垂直对齐，只差 0.5px）。约定写的是 52，改动前需要同步 `task.md`/`plan.md`。
