# 统一牌桌 Agent 与本地数值 — 方案讨论

日期：2026-09-25　基线：`main` @ 3ba346c，另有未提交改动（见「已有改动」）

## 起因（用户原话要点）

1. 我在枪口，教练却说我是大盲；对手 Agent 也会说错自己的位置。
2. 教练对话会丢上下文，不能连续对话。
3. 教练讲解（speak）失败没有重试。
4. 复盘是不是只看我的打法，会不会结合对手手牌和加注习惯？
5. 对手像是乱打；希望一手结束后，场上玩家再发言一次（总结思路或口嗨）。
6. 对手 Agent 和教练 Agent 的上下文管理应该相同；教练就是一个特殊的 Agent，没有操作权，只给建议，靠提示词声明即可。模型用的是 DeepSeek，能力足够，提示词不要把模型当傻子。
7. 规则引擎（胜率 / 出路 / 规则建议）看起来很复杂，而且不准。

## 查证到的现状

- `situation()`（src/main/table/text.ts）是对手和教练共用的局面文本，其中没有按钮和位置信息，座位也按座号列出。模型只能从行动记录里的「X 大盲 100」去猜。引擎里有 `button()`、`blindSeats()`，但没有被用到。
- 对手（agents/opponent.ts）：每次决策单独调用，不带历史；system 是人设加长期印象，user 是局面、最近 8 条公屏和最近 3 手公开结果。强制调用 act 工具，没有先思考的空间。
- 教练：speak 不带历史；ask 带最近 6 轮问答，但把局面放在 system 里；recap 只看本手摘要。speak 和 recap 的输出都不进历史。speak 的超时是 20s，Mastra 不会对超时重试，界面也没有重试入口。
- 本地数值（runner.numsFor、engine/eval.ts）：
  - 胜率：把所有未弃牌的对手当作拿随机牌，蒙特卡洛 400 次（对手决策时 150 次）。
  - 所需胜率：跟注额 ÷ (底池 + 跟注额)。
  - 出路：只看牌型大类是否升级。
  - 规则建议：依赖 1.6 / 2.2 两个经验系数。
  - 胜率和规则建议都写进了对手和教练的提示词。
- ADR-004（river-v2）规定对手每回合一次 act、不带会话历史，也不用 Mastra 存储。

## 已有改动（本次讨论前做的，未提交）

- 已完成：位置修复。新增 `positions(t)`；`situation()` 按行动顺序列出座位、标注位置，并单独写一行「你的位置」；落库记录新增 `HandPlayer.pos`，复盘摘要带上位置；有 3 条测试。
- 已完成：教练讲解失败可重试。`CoachState.retry` 给出可重试条目的 id，`coach.retry` 统一处理复盘重试和讲解重试。讲解重试只在「仍是该决策点、玩家尚未行动」时可用。
- 过渡做法：教练 `history` 统一了讲解、问答和复盘，将被下面的统一 thread 取代。

## 方案

### A. 统一牌桌 Agent（TableAgent）

对手和教练用同一套上下文机制，区别只在三处：

- 人设（system 文案）
- 视角座位：对手是自己的座位；教练是玩家座位，能看到玩家底牌，但本身不占座
- 能力：对手出牌（act 工具）；教练只给建议（流式文本，复盘用 recap 工具）

每个 Agent 在本桌有一条 thread：

- system 固定不变：人设、长期印象、能力声明。
- thread 只追加（缓存只是附带收益，见修订 F3）。

| 事件 | 对手 thread | 教练 thread |
|---|---|---|
| 轮到自己 / 轮到玩家 | user：局面 + 上次之后的新公屏 → assistant：tool-call act → tool：实际行动 | user：局面 → assistant：讲解 |
| 玩家提问 | — | user：问题，局面有变化时附上新局面 → assistant：回答 |
| 一手结束 | 仅入过池的人：user：**公开**结果 → assistant：tool-call talk → tool | user：结果 + 亮出的全部底牌 → assistant：tool-call recap → tool |
| 该 Agent 在新一手第一次被调用 | 代码把所有未压缩的往手压缩为「位置、行动线、结果、自己的想法与发言」（惰性，见 F1） | 同左 |

**用户已定：**

- 本手的局面原样保留；往手的局面压缩，窗口保留约 5 手。
- act 增加 think 字段：不公开，只进该对手自己的 thread。
- 赛后发言交给人设，可真可假；提示词只声明「可以复盘、口嗨、嘴硬，甚至撒谎」。
- 一手结束后发言的是入过池的对手和教练。对手发言异步出现在公屏上，不阻塞下一手；教练局的复盘沿用现有的阻塞逻辑。

**AI 补充，用户已认可：**

- 往手压缩由代码完成，不调用模型。
- 如果对手的赛后发言还没返回、又轮到它行动，就中止并丢弃这次发言，牌局节奏优先。
- 复盘也带 thread，提示词改为「结合对手倾向评价玩家的决策」。
- 长期印象 `note` → `river_memory` 保持不变。thread 只放在内存里，离桌清空。
- 提示词不加打法指引，只声明身份、视角、能力和输出格式。
- 信息隔离仍由 `situation()` 按视角裁剪。对手 thread 只含公开信息（见 F8）。
- 自由局没有教练。

### B. 本地数值

| 项 | 处理 |
|---|---|
| 规则建议 | 删除，面板和提示词里都不再出现 |
| 胜率 | 面板保留，改名为「对随机牌胜率」，模拟 2500 次（见 F6），不再写进提示词 |
| 所需胜率（底池赔率） | 保留，是精确值，照常写进提示词 |
| 当前牌型 | 保留 |
| 出路 | 保留并改口径：下一张牌能让「我的牌型」超过「公共牌自身牌型」的牌数；名称改为「改进牌」；不写进提示词 |
| 面板的「跟注 ±EV」 | 删除：它比较的两个数口径不一致 |

不做「按对手行动推测范围再算胜率」：那是 solver 级别的复杂度，而推测对手范围本来就是模型该做的推理。

### 影响面

- 新增 ADR-006「统一牌桌 Agent 上下文」，修订 ADR-004 中「对手不带会话历史」这一条；存储部分不变。
- 回放页的「让教练复盘」没有牌桌 thread，仍按单手摘要调用。

### 验证

- 单元测试：thread 的追加与压缩；对手 thread 不含 `holeAfter`（摊牌亮牌可以出现）；赛后发言进行中又轮到该对手行动时的放弃逻辑；新的出路口径。
- 实机：打几手，检查对手同一手内的打法是否连贯、赛后发言是否与其 think 相符、教练能否接上自己的讲解继续追问。

## 修订（回应 reviews/design-1.md，另加用户新增要求）

**用户新增**：当前牌型写进局面。`situation()` 按视角加一行「你（玩家）当前的牌型：…」，对手和教练都能拿到。这是精确值，与 B 节「不再写进提示词」的胜率、改进牌不冲突。

**F1 压缩时机与赛后发言的先后**
- 压缩改为惰性执行：新一手里，某个 Agent **第一次被调用时**才压缩它的上一手，而不是在发牌时统一压缩。
- 此时如果它上一手的赛后发言还在进行中，就中止并丢弃；如果已经完成，发言会写进压缩摘要。
- 所以「又轮到该对手行动」就是它唯一的中止点，与原方案一致，不会因为玩家点「下一手」就被提前丢弃。
- 结论：赛后发言只可能在压缩之前完成或被丢弃，不存在「压缩之后才到」的情况。

**F2 thread 写入契约**（「中止/跳过不写」「一次一对」已被第 3、4 轮取代）
- 只有成功的调用写入 thread，一次写入一对 user + assistant。失败、中止、跳过、被丢弃的调用都不写。
- 重试会重新发起完整的一轮，不会重复写入。所以不会出现连续两条同角色的消息。
- 空发言照样写入这一对，assistant 内容记为「（没说话）」。
- 往手摘要不单独成为消息：压缩后，整个 thread 重建为「第一条 user = 【往手回顾】若干手摘要 + 本手第一次观察」，后面按 user / assistant 交替。

**F3 缓存前提**（「入座快照」已被第 3 轮 N2 取代）
- 缓存降级为附带收益，不再作为设计理由。统一 thread 的理由是连贯性：同一手内打法连贯，教练能接着自己的话继续说。
- 能低成本做到的仍然做：
  - 长期印象在入座时取一份快照，本桌期间 system 保持不变，新写入的 note 下一桌才生效。
  - 教练的 system 统一为一份；讲解、问答、复盘的具体要求放在当次的 user 消息里。
- 工具注册的差异和滑动窗口造成的失效接受不管，预期只有同一手内能命中缓存。
- 实机验证时看 `river_usage.cached` 列，只作观察，不作为验收条件。

**F4 act 结果在 thread 中的表示**（「拼成文本」已被第 3 轮取代）
- 由代码拼成文本：`想法：…｜行动：加注到 300｜说：…`。
- 风险：提供方不支持强制调用工具时，会退回 auto 模式，模型可能模仿历史直接回文本。现有行为是「没调用 act 就停下，横幅提示重试」，这一点不变。
- 实施时先确认用户的 DeepSeek 提供方的 `supportsRequired` 实测值。如果是 false，这个风险就从边缘情况变成了主路径，需要带回讨论。

**F5 改进牌口径**（精确定义）
- 设 `rel(牌组) = 我的牌型大类 − 公共牌自身的牌型大类`。下一张牌 c 是改进牌，当且仅当 `rel(加上 c 之后) > rel(现在)`。
- 例 1：7♠7♦、K♣9♥2♠。发出 K 时，公共牌成对，我变成两对，rel 仍是 1，不算改进牌；发出 7 时我成三条，rel 变为 3，算。
- 例 2：A♠5♦、K♣9♥2♠。发出 A 或 5 时 rel 从 0 变为 1，算。
- 只在翻牌、转牌时计算，同现状。

**F6 胜率模拟次数**
- 改为 2500 次：胜率 30% 左右时标准误约 ±0.9%。审阅者本机实测约 80 ms，每个决策点只算一次（现有缓存按 key 生效）。
- 对手不再需要胜率，原先每次决策 150 次的模拟一并去掉。

**F7 入池定义与用量统计**
- 「入过池」指本手自愿投入过筹码（跟注、下注、加注；盲注不算），或看到了翻牌。
- 赛后发言新增用量 purpose `talk`，统计页单独列出。

**F8 信息隔离的措辞**
- 对手 thread 只含公开信息。摊牌时亮出的牌是公开的，可以出现。
- 教练局一手结束时亮给玩家的弃牌者底牌（`holeAfter`）不是公开信息，不能出现在对手 thread 里。

**F9 概率面板**
- 删除「跟注 ±EV」的文字和配色，同时删除进度条上的「所需胜率」刻度线。
- 面板改为并列展示几项事实，不作好坏判断：对随机牌胜率、底池赔率、当前牌型、改进牌。

**F10 影响面补充**
- 测试替身 `AgentDeps` 随新接口一起改。
- 回放页的「让教练复盘」没有牌桌 thread：沿用教练 system，user 里只放单手摘要。
- 交付时更新 `.rivo/knowledge/README.md` 中与 Agent 上下文有关的部分。

## 第 3 轮决定（回应 reviews/design-2.md，并核实 F4）

**F4 核实结果：** 用户本地 `river_providers` 里 DeepSeek 的 `supports_required = 0`，模型为 `deepseek-flash`。这说明 App 现在调用对手时用的是 auto 模式。那次测试失败，也可能只是超时之类的偶发原因（`testProvider` 把任何错误都判为不支持）。

**用户决定：** 历史中的出牌记录写成真实的工具调用，不拼成文本：
- 一条 assistant 消息，内容是 `tool-call act(think, action, to, say, note)`；
- 接一条 tool 消息，内容是 `tool-result`，值为代码规范化之后实际执行的行动，例如 `{ 实际: "加注至 300" }`。模型因此能看到 `normalize` 修正后的真实结果。
- 已验证：Mastra 1.69.0 的 `agent.generate` 接受 AI SDK ModelMessage 格式的 `tool-call` / `tool-result` 消息，并原样传给模型（mock 模型实验，prompt 中两种消息都完整保留）。DeepSeek 真实接口是否接受，在实施的实机验证中确认。它用的是标准的 OpenAI tool 消息格式，风险较低。
- 相应地，`llm.ts` 的 `Msg` 扩展为允许上述两类消息。F2 的「成对写入」对对手来说改为「user + assistant(tool-call) + tool」三条一组。
- 往手压缩后，这些工具调用不再保留原结构，改写成第一条 user 里「往手回顾」中的文本，因为回顾本身就是 user 消息。

**N1 被打断的讲解（用户决定：写入并标记）**
讲解被跳过或中途失败时，只要界面上已经显示了文字，就照常把这一对写入 thread，assistant 内容末尾加「（被打断）」。没有显示任何文字的，仍然不写。

**N2 印象生效时机（用户决定：同现状）**
取消入座时的快照，每次调用都重新读 `memoryOf`，新印象从下一手起生效。代价是有新印象的那一手缓存会失效一次，接受。

**N3：** 正文中的旧措辞已经同步（表格中的压缩时机、F8 措辞、胜率次数）。压缩对象改为「所有未压缩的往手」。验证清单以本节为准：
- 失败或中止、且界面上没有文字的调用不写入；
- 被打断但界面上已有文字的讲解会写入，并带标记；
- 惰性压缩后 thread 的形状：第一条 user 含往手回顾，其后严格按组交替；
- 对手首次调用时中止在途的赛后发言，并丢弃其返回结果；
- 往手摘要和对手 thread 里不含 `holeAfter`，但摊牌亮出的牌可以出现；
- 对手的历史以 tool-call / tool-result 形式出现；
- 改进牌口径覆盖 design-2 表中的各例；
- 实机观察 DeepSeek 在带工具历史、auto 模式下能否稳定调用 act。

**N4：** 2500 次模拟下标准误约为 ±1%（1σ），大约三分之一的时候偏差会超过 1 个百分点。面板只展示，不参与判断，所以接受。

**N5：** 赛后发言在公屏和其他 Agent 的观察里都加「[第 N 手赛后]」前缀。面板上的「底池赔率」改名为「所需胜率（底池赔率）」，与数值口径一致。

**用户新增：加注额可以直接输入**
`ActionBar` 里的加注额改成输入框：回车或失焦时确认，超出范围夹到最小加注和全下之间，输入框聚焦时不触发牌桌快捷键。这一项并入本次交付。

## 第 4 轮决定（回应 reviews/design-3.md）

**M1 复盘与赛后发言的历史表示（用户决定：统一存成 tool-call）**
- 凡是工具产出的内容，历史里都存成 tool-call 加 tool-result：对手出牌 `act`、教练复盘 `recap`、对手赛后发言。
- 赛后发言也是一个工具 `talk(say, note)`，调用方式与 `act` 相同：强制调用，不支持强制时退回 auto。
- 教练讲解和提问是流式文本，存成 assistant 文本。
- 不做按需渲染。已知风险：本次调用不带工具、历史里却有 tool-call 时，部分提供方（如 Anthropic）会拒绝。用户只用 DeepSeek，这个风险接受，在实机验证中确认。如果 DeepSeek 也拒绝，再改为按需渲染（design-3 的 a 方案）。
- 分组统一规则：一次成功调用写入一组，为 user + assistant(tool-call) + tool 三条，或 user + assistant(文本) 两条。「（没说话）」就是 `talk` 的 say 为空，不再特殊处理。

**M4：** 提问和讲解一样：界面上已经显示了文字的，就写入历史并标「（被打断）」。重试讲解时，历史里会留着被打断的那半句，界面上则是重新生成的内容，这一点接受。

**M5 加注输入框：**
- 回车确认数额并失焦，不直接加注；Esc 放弃草稿并失焦。
- 不能加注时禁用输入框。
- 解析时去掉千分位，超出范围夹到最小加注与全下之间。
- 进入新的决策点时，草稿重置为默认加注额。

**M6：**
- tool-result 里记录公屏实际显示的发言（截断后的版本）。
- 给对手的「新公屏」不包含它自己说过的话。

## 第 5 轮补充（回应 reviews/design-4.md，均为 AI 处理的细节）

- **R1 验证项：** 实机验证必须覆盖下面两条路径。任一路径失败（提问报错，或赛后发言始终不出现），就改用按需渲染（design-3 的 a 方案）。
  1. 教练局：复盘出来后先提一个问题，再点下一手。这时历史里有 recap 的 tool-call，本次请求却不带工具。
  2. 对手的赛后发言能正常出现在公屏上。这时历史里有 act 的 tool-call，本次请求只注册了 talk。
- **R2 talk 失败处理：** 没调用工具、调用失败、超时或被中止，都当作「这次没发言」处理：不写入 thread，不重试，不停牌局，不弹横幅。talk 成功返回时，如果带了 note，立即写入 `river_memory`；被中止或失败时，note 一并丢弃。
- **R3 tool-result 内容：** act 写入实际执行的行动，以及公屏上显示的发言（截断后的版本）；talk 写入公屏上显示的发言；recap 写入 `{ ok: true }`。
- **R4：**
  - 第 110 行「（没说话）」、第 111 行「按 user / assistant 交替」均以第 4 轮的分组规则为准。
  - 加注输入框遇到空值或非数字时，回退到输入前的值。
